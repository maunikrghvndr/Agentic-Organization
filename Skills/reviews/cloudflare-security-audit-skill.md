## Conditions

- **C1. Install by pinned git fetch only.** The upstream install path is `npx skills add ...` (`README.md:51-66`), a third-party CLI fetched unpinned from the npm registry. It was not reviewed and is not used. `Skills/install-skills.mjs` fetches the sha above and copies the folder; nothing else is supported.
- **C2. Native Windows: guidance mode only.** Both validators refuse every input when the OS has no `O_NOFOLLOW`/`O_NONBLOCK` (`skills/security-audit/validate-findings.cjs:605-609`, `skills/security-audit/validate-coverage-ledger.cjs:722-727`: "OS no-follow and nonblocking input protection is unavailable"). Node on native Windows does not define those constants, and the skill allows only two end states, one of which needs both validators to pass (`skills/security-audit/SKILL.md:179`). A full audit on native Windows therefore cannot reach "complete". Run full audits in WSL2 or a devcontainer; guidance mode works anywhere.
- **C3. The library's rules stay in force when the skill triggers.** The skill's description makes a host load it on "security questions, focused reviews, vulnerability research, security audits, or pen tests" (`skills/security-audit/SKILL.md:3`). It is guidance by default and says loading it "does not authorize the complete audit workflow or file creation" (`SKILL.md:12-17`), which is the safe default, but a skill's own trigger is not governed by the Grill Checkpoint. When it loads, `AGENTS.md` and `security-engineer.md` still decide scope, findings format and the verdict; the skill adds method, it does not replace the role. A full audit starts only on an explicit request, after one confirmation that states profile and budget.
- **C4. Set a budget for a full audit.** A full run is many sub-agent invocations (four reconnaissance agents, hunter waves, critics, one or two verifiers per candidate: `SKILL.md:121-134`) and upstream publishes no cost figures. The skill supports a strict invocation budget (`SKILL.md:121-123`); use it.
- **C5. The report is sensitive and lives outside the repository.** Full audit mode writes `REPORT.md`, `FINDINGS-DETAIL.md`, `findings.json` and per-agent folders under `~/security-audit-skill/<repo-name>/run-<N>` by default (`SKILL.md:51`, `SKILL.md:56-66`). That is a write outside the repository made by the agent on the skill's instruction. Treat the folder as confidential, do not copy its contents into `.ai-memory/`, and delete it when the findings are closed.
- **C6. Do not run the bundled test files.** `validate-findings.test.cjs` and `validate-coverage-ledger.test.cjs` are copied with the folder but are not part of the workflow. They start child processes (`node`, `mkfifo`) and create and delete temp directories (`validate-findings.test.cjs:5,103-112,466-469`). They are ordinary unit tests and showed nothing hostile, but there is no reason to run them from an installed skill.
- **C7. A new pin is a new review.** Any change of `commit` in the manifest needs this record redone against the new sha (diff from `c1c8a8c` is enough when the history is linear), before the manifest changes.
