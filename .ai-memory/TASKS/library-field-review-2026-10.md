## 1. What changed in the field since the July 2026 restructure

The one-paragraph version: **the ecosystem converged on a three-tier instruction model and on multi-vendor file formats for skills, rules, hooks and subagents; the empirical literature says instruction files do far less than practitioners assume and that enforcement must move from prose to hooks and permissions; verification by someone other than the author became the first-order practice.**

### 1.1 Instruction files and the standards
- **AGENTS.md** is now the cross-tool default: donated to the Linux Foundation's Agentic AI Foundation (2025-12-09), 60k+ projects, read by Codex (32 KiB combined cap by default), Cursor, Copilot, Amp, Cline, Devin/Windsurf (12k chars per rule file), Kiro, Jules and — since **Claude Code v2.1.277 (2026-09)** — Claude Code itself, as a fallback when no CLAUDE.md or CLAUDE.local.md exists. Gemini CLI still needs `context.fileName` configured.
- **Three-tier model everywhere:** a short always-on file (Anthropic's target: under 200 lines), path-scoped rules (`.claude/rules` `paths:`, Cursor `.mdc` globs, Copilot `applyTo`, Kiro `fileMatch`), and on-demand skills. Anthropic's steering guidance (2026-06-18): CLAUDE.md for facts, rules for scoped conventions, skills for procedures, subagents for isolation, **hooks for anything that must happen every time** ("instructions advise, hooks enforce").
- **Agent Skills** (SKILL.md + `scripts/ references/ assets/`) is an open spec at agentskills.io (six portable frontmatter fields; SKILL.md under 500 lines; references loaded one level deep). First-party docs confirm it is read by Codex and ChatGPT (`.agents/skills`), Cursor (`.cursor/skills`, `.agents/skills`, also reads `.claude/`), Gemini CLI, VS Code and GitHub Copilot (page dated 2026-10-14), OpenCode (2026-10-17), JetBrains Junie (2026-10-15), Factory, and Claude Code. `.agents/skills/` is the interop location. **This is the fact that most changes the picture for your tool-agnostic constraint: skills, rules, hooks and subagent definitions are no longer Claude-only.** Hooks exist in Cursor (`.cursor/hooks.json`) and Codex (`.codex/hooks.json`); subagent files exist in Claude (`.claude/agents`), Codex (`.codex/agents` TOML), Cursor (`.cursor/agents`, also reads `.claude/agents`), Copilot (`.github/agents/*.agent.md`).
- **The empirical bad news (2026):** Gloaguen et al. (ETH, arXiv 2602.11988, v3 2026-09-29): context files do not generally improve task success and raise cost over 20%; repository overviews are unhelpful; only non-standard instructions are worth stating. McMillan (arXiv 2605.10039, 1,650 sessions): file size, position and contradictions have **no detectable effect on adherence**, but compliance decays about 5.6% per generated function within a session. arXiv 2608.11095: instruction files grow unboundedly (+226%) because the rationale behind each rule is lost, so nothing is ever safe to delete. Rules that oppose model priors are followed 3.6–7.4 points less. Skill-rule: a static read of an instruction file correlates with its behavioural effect at only rho=0.14 (ACES, arXiv 2608.20614).

### 1.3 Spec-driven development
- **GitHub Spec Kit v1.2.1 (2026-10-16).** Core loop is now `specify → plan → tasks → implement → converge` per feature, constitution once per project; `clarify`, `checklist`, `analyze` are optional quality gates on a "full path". `/speckit-converge` (0.11.2) compares code against spec/plan/tasks and appends "Phase N: Convergence" to tasks.md until Converged. Commands install as Agent Skills (hyphenated `/speckit-*`; dotted form remains the reference spelling for generic command files). `specify` caps open clarifications at 3 and records defaults in a `## Assumptions` section (0.4.1); `clarify` asks at most 5 questions, one at a time; `checklist` = "unit tests for requirements writing" (CHK ids, ≥80% of items cite a spec section, no Verify/Test phrasing). Bundled bug extension: assess → fix → test with verdicts verified/partial/failed and "MUST NOT modify source code" in the test stage. 176 community extensions, YAML workflow engine, experimental MCP server.
- **Kiro** (docs through 2026-10-15): EARS requirements.md + design.md + tasks.md, tiered as vibe / Quick Spec / Feature Spec / Bugfix Spec; dependency-graph parallel task "waves"; property-based tests derived from EARS; `SHALL CONTINUE TO` phrasing for unchanged behaviour; steering with always/fileMatch/manual/auto inclusion.
- **OpenSpec v1.14.3** (delta specs; explore → propose → apply → archive; verify); **BMAD** v6.12 stable, V7 alpha repackaging as skills.
- Critique is stable: Thoughtworks Radar "Assess" (2025-11) warning about long, hard-to-review specs; Scott Logic measured 23–33 minutes and 2,200–2,600 lines of markdown for a 300–700 LOC feature vs 8 minutes by incremental prompting. Practitioner consensus (mid-2026): 1–3 page specs, explicit out-of-scope, spec-anchored, constitution first, tests as the enforcer, skip the heavy path for small changes. **No quantified evidence yet that SDD reduces defects.**

### 1.4 Multi-agent orchestration and review
- The 2025 "multi-agent vs single agent" debate resolved into **"many readers, one writer"** (Cognition, 2026-04-22: writes stay single-threaded; parallel-writer swarms remain "mostly a distraction"). Read-only fan-out (search, exploration, review) is the shipping pattern in Devin, Claude Code, Cursor, Codex and Copilot.
- Anthropic's harness post (2026-03-24): agents "reliably skew positive when grading their own work"; the grader must be a separate agent. Self-authored verification is unreliable (arXiv 2607.24300); self-repair helps only when driven by external executable feedback.
- **Cross-Context Review** (arXiv 2603.12123, v2 2026-10-01): a *second* review in a fresh session beats a repeated same-session review (F1 28.6 vs 21.7), but is **not significantly better than a single careful same-session review** (27.1). Structured disagreement and cold-start reviewers cut false consensus (Adversarial Review, ICML 2026 DL4C; Refute-or-Promote 2026-04: ~79% of candidates killed by a mandatory empirical gate). Same-model-family judge bias is 3.4–8.4 points (open-weight families measured), which argues for cross-model second opinions.
- Anthropic's documented verification ladder: (1) ask for the check in the prompt → (2) `/goal` prompt-judged evaluator → (3) deterministic Stop hook → (4) fresh-context subagent or workflow that tries to refute the result. "Have Claude show evidence rather than asserting success."
- Tooling: Cursor 3.x `/worktree`, `/best-of-n`; Codex cloud `--attempts 1-4`, stable `codex review --base`; Copilot code review agentic (2026-03-05); Codex and Copilot read review rules from AGENTS.md (`## Code Review Rules`, P0/P1 only).

### 1.5 Context engineering, memory, and self-improvement
- Always-on files must be small (Anthropic: under 200 lines; HumanLayer: frontier models follow ~150–200 instructions reliably; IFScale: best models 68% at 500 instructions, with primacy bias). Chroma's Context Rot report: degradation with input length even on trivial tasks.
- **Self-evolving context is a research line with a clear warning:** ACE (ICLR 2026) and Dynamic Cheatsheet show *itemized, incremental* playbook updates beat monolithic rewrites, which suffer brevity bias and "context collapse" (one documented collapse: 18,282 → 122 tokens, accuracy 66.7 → 57.1). Memory Transfer Learning (2026-04): abstract insights transfer; low-level traces cause negative transfer. ACL Findings 2026: accumulated benign experience erodes safety/refusal. SWE Context Bench: well-selected distilled experience lifts resolution 26 → 34%, but agent-selected retrieval drops it to 22%, below baseline.
- Always-on vs on-demand context: a 288-run ablation (2026-07) found **no correctness difference**, only lower cache-creation tokens for on-demand.
- Products: Claude Code auto memory (above); Codex memories (opt-in, two-phase extraction, git-backed, "keep required rules in AGENTS.md"); Hermes Agent (hard caps 2,200/1,375 chars, overflow forces consolidation, agent-written skills with a curator); Letta Code Context Repositories (git-backed memory, `/doctor memory`); Karpathy's LLM Wiki gist (2026-04-04: raw → wiki → schema; ingest/query/lint). Practitioner rule-mining: teams grow rules mainly by adding negative constraints after errors; updates raise compliance ~23 points; emerging loops add provenance, ~60-rule caps, last-hit retirement, CI linters (driftlint, `/doctor prompt-audit`).
- Code indexing: Graphify ~127k stars (tree-sitter, git-hook rebuild). **Verified on this machine:** graphifyy 0.9.25 implements `GRAPHIFY_OUT`, `graphify hook status` and `GRAPHIFY_SKIP_HOOK` exactly as AGENTS.md says (undocumented in the upstream README). The only factual error in AGENTS.md is `extract --update`: the real command is `graphify update <path>`. PyPI latest is 0.9.92.

Anthropic's skill-creator runs the same loop (blind pairwise, 60/40 train/validation description optimisation).

Anthropic measured 6 points of pure infrastructure noise on Terminal-Bench 2.0; be skeptical of leaderboard gaps under 3 points.
- Observability: Claude Code exports OTel metrics (cost, tokens, LOC, commits) and events (tool_result, skill_activated) with skill.name / agent.name attributes; **repositories cannot enable telemetry**, only user or managed settings. ccusage reads local logs for 18 agent CLIs (Claude Code, Codex, Copilot CLI, Gemini CLI…).

### 1.7 Security of the agent itself
- Prompt injection through content the agent reads is **unsolved**: a 2026 SoK (78 studies) reports over 85% attack success against state-of-the-art defenses. Real incidents: rules-file backdoor (Pillar, 2025-03), GitHub MCP "toxic agent flow" (Invariant, 2025-05), Cursor CurXecute (CVE-2025-54135), **AGENTS.md written by a malicious dependency during `go mod tidy`** (NVIDIA, 2026-04-20), claude-code-action hijacked by a single GitHub issue (fixed in Claude Code 2.1.128, 2026-05-05; CVE-2026-47751: malicious `.mcp.json` in a PR → RCE on the runner), CVE-2026-33068 (repo `.claude/settings.json` set `bypassPermissions` and skipped the trust dialog), Mini Shai-Hulud (2026-05: valid npm provenance on compromised packages; hooks injected into `.claude/settings.json`). Microsoft's prescription: declare issue/PR/file content "untrusted data, not instructions" **and** apply Meta's Agents Rule of Two (never combine untrusted input, secret access and external write in one autonomous run).
- Frameworks: OWASP Top 10 for Agentic Applications ASI01–ASI10 (2025-12-09); OWASP LLM Top 10 **2026 edition** (announced 2026-09-01; the library still cites 2025); MCP spec Security Best Practices (confused deputy, token passthrough, state-handle hijacking, local server consent).
- Vendor primitives: Claude Code OS sandbox (`/sandbox`; macOS Seatbelt, Linux bubblewrap; **no native Windows sandbox — your platform runs Bash unsandboxed**), deny > ask > allow rules (Bash rules are text matches, "not a security boundary"), least-privilege subagents, workspace trust gating of repo-supplied settings/hooks/MCP — but hooks in settings files and `.mcp.json` servers still run in `-p`. Skill supply chain: Snyk ToxicSkills found 13.4% of 3,984 marketplace skills with critical issues (vendor claim); Trail of Bits bypassed three skill scanners (2026-06-03); CSA: scanners are a layer, not a gate. Slopsquatting: 5.2% (commercial) / 21.7% (open) of model-suggested packages do not exist (USENIX Sec 2025).

### 1.8 Headless automation
- Hand-rolled "shell script pipes a role prompt into `claude -p`" is superseded on every platform: claude-code-action v1 (`prompt` + `claude_args`, label/assignee triggers, `--json-schema` structured output, no PR by default, write-access and bot checks), Routines, Codex `exec --json --output-schema` and `openai/codex-action@v1`, Copilot cloud agent Automations (2026-06-02), Cursor Cloud Agents with Linear/Sentry/PagerDuty triggers. Official remote MCP servers from Linear (read-only endpoint available) and Atlassian are the standard way agents read tickets.
