# What this library can inherit from its peers

Final researcher report — 2026-10-18. Scope: Hermes Agent, BMAD-Method, OpenSpec, GitHub Spec Kit, Kiro, cc-sdd, Multica, Letta Code. Library constraints and open Decisions A/B/C taken as settled inputs. Library baseline for every byte count below: `AGENTS.md` = 32,415 B / 193 lines (353 B under the Codex 32,768 B cap).

## Method and trust

**What ran.** For each of the eight systems: (1) a researcher pass that read primary sources (repo source, templates, skill files, docs trees at a pinned commit or tag) and wrote a mechanism inventory with per-mechanism `verified` / `claimed` labels; (2) a gap check that mapped every mechanism to the library on disk (`AGENTS.md`, `EngineeringTeam/*.md`, `_shared/*`, `LESSONS*`, `MemoryTemplates/*`, `Scripts/*`, `Hooks/*`) with `path:line` citations and a status of have / partial / lacking; (3) three independent skeptic passes per system, each with a fixed lens — **E** (evidence: re-open the primary source, confirm existence and currency, downgrade where the source disagreed, default reject when uncertain), **C** (constraints: tool-agnostic, no runtime, full-depth roles, update-never-delete, style Blocking; anything needing A/B/C → defer), **V** (value for a solo engineer in one session on Claude Code / Codex / Cursor; gates and templates over prose; ceremony rejected). Each skeptic returned adopt / adapt / defer / reject per mechanism with a concrete change.

**How verdicts were formed.** 105 mechanism-verdicts (109 mechanisms; four were already "have" and not voted). Consensus rule as instructed: **Adopt now** = at least two skeptics adopt/adapt and none reject; **Defer** = majority defer, or the only portable part hinges on A/B/C; **Reject** = majority reject. Where a mechanism got two adapts and one reject it fails the adopt rule; those are listed under Reject in a separate "split verdict" group with the dissent, because they are the owner's call, not mine. Where skeptics agreed on the verdict but proposed different wordings, the Adopt section names the variant and the alternative.

**Honesty notes (condensed).**
- Official docs hosts were unreachable from the sandbox for every system (hermes-agent.nousresearch.com, docs.bmad-method.org, openspec.dev, github.github.com/spec-kit, kiro.dev, multica.ai, docs.letta.com) — all docs content came from the repos' docs source trees at the pinned commit, so the live sites may lag or lead. GitHub REST/`gh` returned 403 for most repos; release dates are page-rendered or CHANGELOG dates, not API timestamps.
- Kiro was read almost entirely via third-party verbatim mirrors of kiro.dev `.md` pages plus the official KiroCrew/powers repos; its Memory (CLI 2.29), Powers format, Analyze Requirements body, subagent isolation and IDE 1.3.11 panel are search-snippet claims only. Kiro's memory feature was downgraded to *unverified*.
- Letta: skeptic C could not re-fetch any Letta source (repo attach denied); verdicts rest on the researcher's inventory. Two researcher claims did not hold on re-fetch: the "do not raise or disable these limits" error text, and "AGENTS.md linked rather than copied".
- Corrections recorded by skeptics and applied here: Hermes "declarative facts / stale within a week" lives in `agent/prompt_builder.py`, not the memory docs page; Hermes `DEFAULT_MAX_VERIFY_NUDGES = 3` is in `verify_hooks.py` (not `verification_stop.py`, whose builder defaults to 2); BMAD "keep completed plans as evidence" and "~40-page input ceiling" were not found; BMAD V7 had no tag as of 2026-10-18 (ETA passed); Spec Kit `before_/after_converge` hooks are referenced by `converge.md` but absent from the extension API reference (dated 2026-01-28); Spec Kit spec-template does not mark Assumptions mandatory; OpenSpec `docs/agent-contract.md` is self-dated 2026-06-11 and omits task `sourcePath/line` fields; cc-sdd File Structure Plan is gate-checked, not template-required; Multica `pending/` restart survival is implied by on-disk JSON, not stated; Multica project workflows shipped two days before review with no end-user docs page.
- No system in the set publishes a measured benefit for its memory/skills/gates mechanisms except Hermes' `toolperf_abeval` (turn/tool-call reductions on one model, n=3 noted as noise by its own README). Every "benefit" elsewhere is design intent.
- The library's own lint (`Lint-Library.ps1`) was not run in this session (no PowerShell in the container); byte counts are from `wc -c`.

### Hermes Agent (NousResearch) — v0.22.2 (2026-10-15), source at main `ccc6956` (2026-10-18)

Self-hosted personal agent whose headline is a closed learning loop: the agent writes its own two capped memory files and its own SKILL.md skills, is nudged every N turns, and a forked background copy reviews each turn and writes memory/skills after delivery. Reliability comes from bounds and gates rather than free growth: hard character caps with no auto-eviction, a curator lifecycle (stale 14 d → archived 30 d, never deleted), a mutation ledger with rollback, optional human write-approval staging, a never-approvable command blocklist, an opt-in verify-before-finish gate, and shadow-git checkpoints. Two invariants shape it: the per-conversation prompt cache is never broken mid-session, and the core is a narrow waist. The repo's own `AGENTS.md` hub enforces byte budgets and complexity ratchets by script, and an A/B harness scores from traces, not self-report.

### OpenSpec (Fission-AI) — v1.14.3 (2026-10-17), HEAD `c794978`

## Reject, and why
