## 2. Proposals

All five are edits to library files, so each is **ask-first** (`AGENTS.md` → Boundaries: role files, `LESSONS`, library scripts) and P1–P3 and P5 touch agent-configuration files (`EngineeringTeam/**`, `MemoryTemplates/**` per `_shared/rules-detail.md:21`) → **mandatory `security-engineer` review** before they count as done. All are additive lines; nothing is removed or compressed. Ordered by value.

### P4 — EVALS isolation, truncated trials, hidden checks (mechanisms 21, 16, 15, 22) — highest value

- **Target:** `EVALS.md`, section `## What every run records` (line 25), three new bullets appended after the **Trap tasks** bullet (line 37), before the "Row format" paragraph. `AGENTS.md` cost: 0 B.
- **Proposed wording:**

  ```markdown
  - **Isolation (added <date>, SkillOpt):** each trial runs with no instruction source other than the arm under test: no user-level instruction file, no host per-machine memory, no installed `Rules/`, `Hooks/` or `Agents/` overlay, and no copy of the section under test inside the task repo (`rg` the removed text in the repo and in the user-level config before arm B). Record how in the row (`isolation: claude -p --bare` / `codex exec` with a clean `CODEX_HOME` / `Cursor: not isolable`). A run whose isolation was not confirmed is logged `exploratory`, never as a verdict — do not fall back to an unisolated run and keep the number.
  - **Truncated trials:** a trial stopped by a turn, time or cost cap is recorded `truncated`, not pass or fail, and is re-run with the same cap raised for both arms; an arm with a truncated trial has no pass^3.
  - **The check stays outside the session:** the trap's checking script, the trap number and the expected result are never in the task prompt, the task repo or any file the session can read. A failure observed inside an eval arm is an eval result — it is never written up as a Retro lesson or a new trap.
  ```

- **Row format:** add ` — isolation: …` after `host/model/effort: …` in the row template at `EVALS.md:41` (old rows keep the legacy shape, as the file already does for pre-2026-10-18 rows).
- **Tool-agnostic check:** the rule is host-neutral; flags appear only as examples, as the Cost bullet already does. Cursor is stated as not isolable rather than left silent.
- **Lost by not adopting:** the three A/Bs queued in `EVALS.md:43-47` (notably #3, AGENTS.md with vs without the graph section, and the cross-role security dedup) can report `CUT`/`TRIM` because arm B silently still had the rule from a user-level file or an overlay. A false `TRIM` "authorizes removal" (`EVALS.md:57`), so the error is not self-correcting. A capped arm-B trial would be counted as evidence the section is load-bearing.

### P3 — Lapse-or-gap decision before a lesson is proposed (mechanism 9)

- **Target:** `EngineeringTeam/_shared/rules-detail.md`, section `## Self-Learning — when to write a lesson` (line 36), one new paragraph after the existing one at line 38. Not `LESSONS.md` (its "Rules for this file" is always-read by every role; `rules-detail.md` is read on demand) and not `AGENTS.md` (0 B).
- **Proposed wording:**

  ```markdown
  **Lapse or gap — decide before proposing (added <date>, SkillOpt).** For the failure behind the Retro, `rg` the library and the repo memory for a rule that already forbids it. (a) **Gap** — no rule covers it: propose the one-line lesson as above. (b) **Lapse** — a rule covers it and was not followed: never propose a second wording; the Retro reads `Lessons: lapse — <file:line of the existing rule>`, with at most `REINFORCED [date]` on the existing line. A second lapse on the same rule is a request for enforcement, not for prose: propose one of — a lint rule (`Scripts/Lint-*.ps1`), a hook check, a row in `Evals/trap-tasks.md`, or moving the rule to the role file that owns the step — and say which. (c) **Misfire** — the rule was followed and produced the failure: surface it to the user (`LESSONS.md` → Rules for this file).
  ```

- **Lost by not adopting:** the lesson files keep growing with reminders of rules that already exist (the evidence-row failure is already "recorded four times" per `Evals/trap-tasks.md:8` — a lapse, not a gap). SkillOpt's own measurement of ungoverned reminders (best-on-val 70.87% vs final 56.60%, vendor data, one model) is the only number available on this, and it points the same way as `LESSONS.md:45`. Counter-note: that number is single-source and not reproducible from the repo; the proposal stands on the library's own recorded recurrence, not on it.

### P1 — Prompt eval acceptance: ties, noise, per-case flips, rejected candidates (mechanisms 1, 3, 11, 18)

- **Target:** `EngineeringTeam/prompt-engineer.md`, section `## Evaluation And Optimization Standards`, four bullets appended after line 63 ("Do not overfit prompts to the eval set; keep a held-out set of real cases."). Mirror check in `EngineeringTeam/ai-reviewer.md`, Prompt Review, after line 55. `AGENTS.md` cost: 0 B.
- **Proposed wording (`prompt-engineer.md`):**

  ```markdown
  - **Compare paired, on the same cases.** Run the current and the candidate prompt on the identical case list, model id and settings; report the cases that flipped (pass→fail and fail→pass by case id), not only the two totals.
  - **Know the noise before reading a delta.** On a sampled model, run the current prompt at least twice more on the set; a candidate whose gain is within that run-to-run spread is `no evidence`, not an improvement.
  - **A tie keeps the current prompt** — unless the candidate is shorter and no case flipped to fail. Any flip to fail on an adversarial, injection or safety case blocks the change whatever the total.
  - **Log rejected candidates** beside the version history: the change tried, score before → after, the cases that regressed. Read that log before proposing the next change; do not re-try a rejected wording without a new reason.
  ```

- **Proposed wording (`ai-reviewer.md`, after line 55):**

  ```markdown
  - Compared on the same cases with the flipped case ids listed? Gain larger than the current prompt's own run-to-run spread? No adversarial/safety case flipped to fail?
  ```

- **Lost by not adopting:** "before/after" with two totals accepts a +1 change that is sampling noise (the library already learned this for extraction reads at `LESSONS/data-ml-ai.md:9`) and hides a safety case that regressed behind a net gain. Caution carried from the deep read: SkillOpt's hard gate "rejects every candidate and training stalls" on small sets and did not win on accuracy for strong models — hence the noise rule and the shorter-on-tie exception rather than a bare strict `>`.

### P2 — Eval-set hygiene: content-disjoint sets, no checker text in the prompt, judge fails closed (mechanisms 5, 15)

- **Target:** `EngineeringTeam/prompt-engineer.md`, same section, after the P1 bullets; one item added to the `## Final Self-Checklist` and one clause to the Strict Do Not Do list. `AGENTS.md` cost: 0 B.
- **Proposed wording:**

  ```markdown
  - **Keep the sets disjoint by content, not by id.** A few-shot example, or a case used to tune the prompt, must not also appear — verbatim or as a near-duplicate — in the eval or held-out set; check before each run and move or drop the twin. A score from overlapping sets is reported as `not a validation`.
  - **Never write the check into the prompt.** A regex, keyword list, rubric sentence or expected output taken from the eval's checker or from a failing case does not go into the prompt; describe the behaviour wanted, in words that would hold for a case you have not seen.
  - **A judge that cannot score has not scored.** An LLM-judge reply that is unparseable, out of range or empty is a failed measurement for that case (`NOT MEASURABLE`), never a 0 and never a pass; report the count with the result.
  ```

  Checklist line: `- Are the tuning, few-shot, eval and held-out cases disjoint by content, and is the prompt free of checker text?`
  Do-not clause: `copy a checker's pattern or a case's expected output into the prompt;`
- **Lost by not adopting:** a prompt can reach 100% on its eval by containing the eval's own answers or patterns while `prompt-engineer.md:63` is nominally satisfied; a broken judge reads as a regression or as a pass. These are the exact defects SkillOpt had to fix after release (#310: "four ways invalid evidence could reach the gate").

### P5 — `Reconstructed` evidence label (mechanism 19) — lowest value, cheapest

- **Target:** `MemoryTemplates/TASK_MEMORY.template.md`, `## Evidence`, one line after line 38 (the Freshness line); matching sentence in `EngineeringTeam/_shared/rules-detail.md` under `## Compaction / re-entry (Phase Protocol)` (line 64). Optional follow-up, separate change: `Scripts/Lint-RepoMemory.ps1` R7 counts a `Reconstructed:` line as not satisfying the Evidence requirement. `AGENTS.md` cost: 0 B.
- **Proposed wording (template):**

  ```markdown
  - Reconstructed: a row not written from the command's own output in this session (rebuilt after a compaction, or copied from an earlier report) is written `Reconstructed: <command> | <claimed result> | source: <where the claim came from>` and counts as "not verified" until re-run; a field you do not have stays `MISSING`, never inferred.
  ```

- **Proposed wording (`rules-detail.md`, Compaction section):** `After a compaction, never re-type an Evidence row from the summary: keep the rows already on disk, and label anything rebuilt as `Reconstructed:` (task template → Evidence).`
- **Lost by not adopting:** a recalled row has a command and an exit code, so it passes lint R7 and the reviewer's "Evidence row" check while proving nothing. Low frequency, but it is the one path where the Evidence rule can be satisfied without a run.

## 3. Not proposed, and why

- **6 Slow update, 8 marker regions, 24 semantic-density bonus:** Reject (reasons in the table). 8 would replace a write-path control with an in-file one, against `LESSONS.md:45`.
- **17 dream variants / recall, 23 session-end marker, 20 handoff file protocol, 2 decay schedule:** no library use; thin or no evidence in the source.
- **Installing or running SkillOpt-Sleep against the library or user repos:** Reject. It would (a) harvest local transcripts and send excerpts to a provider ("Outbound prompts are not currently guaranteed to be secret-free") — conflicts with the Never list on secrets and needs a `security-engineer` review; (b) write `CLAUDE.md` / `SKILL.md` — conflicts with "no CLAUDE.md shim" and the ask-first Boundary; (c) add a plugin and a Python dependency — conflicts with "works from `AGENTS.md` alone" / no plugin dependency; (d) with `--auto-adopt`, open a persistent prompt-injection path from transcript text into instruction files, which `AGENTS.md:190` forbids ("an unattended run never writes the library").
- **Observation outside this repo's mechanisms (not verified beyond the script header):** `Scripts/Sync-AgentsMd.ps1:25` states it overwrites customized `AGENTS.md` files; a target repo whose path line was corrected under Role library resolution step 2 would be reset by the next sync. Not a SkillOpt finding; noted because mechanism 8 prompted the check.

## 4. Evidence quality of the source (carried forward so proposals are not over-sold)

- Vendor-run, mostly single-seed numbers; raw artifacts for the gating ablations are not public; star count, tracker content and paper results were Unverified in the deep read.
- The gate's measured value is bounding downside for weak models, not accuracy for strong ones; the library proposals therefore borrow the *hygiene* (isolation, disjoint sets, fail-closed judges, truncated ≠ failed, lapse ≠ gap), not the optimizer.
