## Cross-cutting findings

- **F-1 (Confirmed) — a factual error in the gap file that affects P-5.** It says "the engineer role files already point at `rules-detail.md`". They do not: `rg -c rules-detail` returns 0 for `backend-engineer.md`, `frontend-engineer.md`, `ai-engineer.md` and `qa-engineer.md` (1 for `planner.md`). A rule added to `_shared/rules-detail.md` is reached only through an `AGENTS.md` "Full rule:" pointer. P-6 (Undo / Parallelism pointers exist) and P-14 (Compaction pointer exists) are reachable; a new "Deviations" section is not, and `AGENTS.md` has no room for a pointer.
- **F-2 (Confirmed) — upstream evidence is weaker than "popular", and the source says so.** The one measured result (P-2's basis) is described upstream as "n=27 verdicts (3 models × 3 conditions × 3 tasks), 1 rep — direction-finding, not powered" (`gsd-core/references/honest-verifier.md:84-85`). Everything else is an issue-number incident or nothing. No proposal can be adopted on GSD's evidence; the ones that survive do so on the library's own recorded failures or on a checkable fact.
- **F-3 — source citations I re-opened and found accurate:** `failing-direction.md:13` (#3172, 21 unrunnable commands); `docs/adr/4309-criterion-baseline-notation.md:11` and `CHANGELOG.md:17` (gate "already holds at HEAD"); `honest-verifier.md:15,21,26,76-77` (100% → 17%, 67%, 2/2, 1/2); `prohibition-probe.md:8` (0/8); `agents/gsd-executor.md:215,264-270,610-617` (no similar-name install, scope boundary, 3 attempts, shared stash); `hooks/gsd-write-guard.js:7-24` (#973, 16-line read over a 292-line file, advisory reasoned past); `execute-phase.md:455` (~1000 files); `src/package-legitimacy.cts:96-97` (30 days, 1000 downloads); `hooks/lib/hook-exit.js` (#3911); `hooks/gsd-secret-read-guard.js:13-16` (the 2.1.259 claim), 3,126 lines; `scripts/lint-gate-positive-control.cjs`; `.out-of-scope/` 32 entries; `agents/gsd-plan-checker.md:44-45` (`required_property`, `fix_hint`); `context-budget.md:106-121` (sizing).
- **F-4 — one source link that does not hold.** P-14 is attributed to mechanism 26, but `gsd-core/references/untrusted-input-boundary.md` contains no mention of compaction or summaries (`grep -i compact|summar` → nothing); only the scanner hook's comments mention it. P-14 is in effect an original proposal, not something GSD ships or tested.

## Per-proposal judgement

### P-1 — Adopt now (trimmed). Verification: Confirmed.
Evidence: both upstream citations are accurate, but they are incident notes, not a measured effect. The gap is real: `planner.md:78` asks for "an observable check, not 'code compiles'" and the template line (`planner.md:193`) has no failure signal; the RED row covers tests only. Constraints: none broken; about 430 bytes in a file loaded only in the planner phase. Value: it stops a phase closing on a check that was green before any work (docs, config, count or grep done-whens), which the library's own `LESSONS.md:46,49` show is a failure it has already had in another form. What I would cut: the `at Baseline: <value>; expect: <op> <value>` notation is new ceremony the planner cannot always fill, because the planner does not run code; and "a check that cannot run in this repo is a gap" restates the Boundaries line on recorded commands. Cheaper form that keeps the benefit: one sentence requiring the exact command plus the output that means failure, and one clause that the engineer records the check failing before the work as an Evidence row (the RED rule extended to non-test checks). No eval needed: it adds no judgement call, only a field.

### P-2 — Adopt after an eval. Verification: Probable.
Evidence: the figures are quoted correctly, but F-2 applies, and upstream also records a cost: "a false tag made the strongest model over-abstain on a real spec-determined bug". More important, the experiment measured a different thing. Upstream's tag marks a requirement whose answer is not in the spec (a blind spot); the proposal re-uses it for criteria that need an external run (load, a real system, production-shaped data). The numbers do not transfer. The library gap is real but narrower than stated: QA already has `Not verified (<reason>)` capping the verdict (`qa-engineer.md:454`) and requires its own Evidence rows; what is missing is only the spec-time trigger. Constraints: none. Value: prevents "Met" on a mock-only test for an integration criterion, a plausible failure in the user's pipeline work. Cost: about 550 bytes over two role files plus a tag the analyst must judge on every criterion, with over-tagging pushing verdicts to Ready With Risks. The gap file's own trap task is the right gate; adopt only if the untagged baseline scores Met on it.

### P-3 — Adopt now. Verification: Confirmed for the gap; the 0/8 figure is Unverified (stated upstream, no raw data).
Evidence: `rg -i "shall not|must never|must not" EngineeringTeam/analyst.md` returns nothing, so the "prohibitions missing" classification is true; the EARS conditional form at `analyst.md:119` handles an event, not a standing rule. I confirmed lint R9 still passes (`Lint-RepoMemory.ps1:144` tests `\bSHALL\b`). Constraints: none; about 550 bytes over two role files; host-neutral. Value: this is a question to the user, so its worth does not depend on GSD's numbers. Must-never rules (never send from a non-production environment, never write PHI to a log) are exactly what a solo developer knows and does not volunteer, and today they surface only when `security-engineer` infers them after the code exists. Cost is one grill question per feature. Caveat to carry into the wording: a prohibition is unbounded, so the QA line should say the negative test attempts the named behaviour through the entry points the feature adds, not "proves it never happens".

### P-4 — Adopt now, recorded as a lesson promotion, not as a GSD adoption. Verification: Confirmed.
Evidence: GSD has no measurement for its four levels. The library has its own: `LESSONS.md:48` (2026-09-29, a validated table with no writer) and the promotion route at `LESSONS.md:22,26`. That is first-hand evidence, which is stronger than anything in the source. Constraints: none; about 520 bytes in `qa-engineer.md`. Duplication check: the seams row (`qa-engineer.md:469`) and the liveness check cover cross-phase contracts and startup, not "who calls this symbol", so the rule is not a duplicate; but after promotion the lesson line must be removed (`LESSONS.md:26`), otherwise it is. Value: the traceability matrix can currently be filled with a `path:line` nothing reaches. Trim: the wording packs three checks (caller, stub, data arrives) into one bullet; the stub clause overlaps `backend-reviewer.md:83` and can go.

### P-5 — Adopt after an eval for the attempt cap only; the rest Reject. Verification: Confirmed.
Evidence: the upstream text exists; upstream evidence is none. Three of the four bullets restate existing rules: "stop and ask" is the ask-first list and `backend-engineer.md:1459`; "record, do not fix" is `AGENTS.md` "clean up only your own mess … mention pre-existing dead code but do not delete it" plus "no unrelated refactors"; "fix your own defect" was never in doubt. Only the cap on repeated attempts at one failing check is new (no match for an attempt cap anywhere in the library). Constraint problem: F-1. The section would sit in `rules-detail.md` with nothing pointing at it from `AGENTS.md` or from any engineer role file, so on every host it would be dead text; fixing that means editing up to twelve engineer role files or spending `AGENTS.md` bytes that do not exist. Value of the cap: real (retry loops burn tokens and tend to end in a weakened test), cost small. Route: an `EVALS.md` trap where the check cannot pass by local patching; if the current library already stops and routes to `debugger`, drop it; if it loops, add one sentence to the existing Rework-loop text, which is reachable. The template widening (Target 2) only makes sense if the section lands.

### P-6 — Adopt now (trimmed); the settings entries Defer. Verification: Confirmed.
Evidence: the stash hazard is a fact, not an anecdote. I reproduced it: a stash pushed in a linked worktree appears in `git stash list` from the main worktree. The library's Undo rule (`rules-detail.md:80`) recommends `git stash push -u` without excluding worktree phases, and `:83` is the only place parallel writers exist, so the library contradicts itself in the one spot where it matters. `rg` finds no `stash`, `restore` or `update-ref` in `Settings/claude-baseline.settings.json`. Constraints: none; about 560 bytes in a file read on demand through existing `AGENTS.md` pointers; plain git, host-neutral. Value: `[P]` phases are rare for a solo developer, so frequency is low, but the loss (another phase's uncommitted work) is silent. Trim: keep "never stash in a worktree phase; checkpoint by commit" and the where-am-I check (toplevel, branch name, `merge-base --is-ancestor`). Drop "if the parent has moved past `Base:` on a path the phase owns, the phase runs sequentially": with disjoint `Owns:` that state is already a one-writer violation, and the phase has no reliable way to detect it. Settings part: `Bash(git restore *)` on the ask list would prompt on `git restore --staged`, an everyday harmless command; that is prompt fatigue for a rare risk. Revive when a destructive `restore` or `stash drop` incident is recorded in a Retro.

### P-7 — Adopt now; the lint is the control, the prose is its explanation. Verification: Confirmed.
Evidence: the upstream incident is quoted accurately, and the same file says an advisory was read and reasoned past, which is evidence against adopting the prose alone. "Missing" is true: no rule in `_shared/memory.md`, `rules-detail.md` or `AGENTS.md` mentions writing a file from a partial read, and `Lint-RepoMemory.ps1` R1–R11 / RW1–RW3 compare nothing against the committed version. Constraints: none; supports update-never-delete instead of bending it; PowerShell is already the lint's language. Value: memory loss is the failure the library's central rule exists to prevent and it currently has no check. Limits to state honestly in the wording: RW4 compares to `HEAD`, so it catches a shrink only before it is committed, and only when someone runs the lint; legitimate splits to `wiki/` will warn (acceptable for a warning, and the dated-note rule tells the reader why). Cost: about 430 bytes in `memory.md` and about 15 lines of script, plus one fixture if P-12 lands.

### P-8 — Adopt now (trimmed). Verification: Confirmed.
Evidence: the thresholds and the no-substitute line are in the source; the thresholds have no cited basis (the gap file says so). The library's own prior research cites the slopsquatting measurement (`library-field-review-2026-10.md:211`), so the risk has independent evidence. Gap check: `security-engineer.md:711` says "real history and maintainers" with nothing recorded, and no file contains a rule against installing a near-match (`rg -i "similarly|near-match|substitut"` → nothing). Constraints: none; a dependency is already ask-first, so this fires rarely. Keep: the "name that does not resolve is reported as not found, never replaced by a similar name" sentence (the one concrete failure path, costs one line) and the Evidence row fields. Cut or soften: the 30-day figure is an unsupported number; state "recently published" as a named risk for the user and leave the number out, or it will be read as a measured threshold. The registry lookup needs network access the session may not have; then the row is `Not verified`, which the wording should say.

### P-9 — Adopt now as a verification task; part of it is answered here. Verification: Probable.
This is not a change, and `Settings/README.md:3` already tells the maintainer to re-verify. From the permissions page as fetched today: (2) negation is valid: "A deny or ask pattern that starts with `!` is a gitignore negation. It carves the paths it matches out of the `path` or `./path` rules listed before it", so `Read(!.env.example)` after `Read(.env.*)` on the baseline's lines 27-30 is correct syntax, in the correct order. (3) "Read and Edit deny rules apply to Claude's built-in file tools, to file commands Claude Code recognizes in Bash, such as `cat`, `head`, `tail`, `sed`, and `tee`, and to the targets of Bash redirections … They don't apply to … arbitrary subprocesses that read or write files indirectly": so `cat .env` is covered, `python -c "open('.env')"` is not, and the sandbox remains the control, which matches `Settings/README.md:25`. (1) Still Unverified: GSD's claim that since 2.1.259 any `Read()` deny rule makes `cd DIR && cat relative-path` prompt. The page lists only `cd` with `git` and `cd` with a redirect as prompting combinations; confirming or refuting needs a live run on the installed version. I agree with not adopting the 3,126-line guard. Cost: one dated README line after a short live test; it is a security-posture file, so the `security-engineer` pass applies.

### P-10 — Defer. Verification: Probable (sizing lines confirmed in the source; the ADR's "unchecked heuristic" remark taken from the deep read).
The gap file itself asks for an A/B and reports "nothing measured" as the loss. The source's numbers have no evidence, and the bullet pushes against a deliberate library rule (`planner.md:110` "Do not create ceremony"). A "justify in one line or split at about 10 files" rule adds a judgement the planner will satisfy by writing the line. Trigger to revive: `Evals/trap-tasks.md` trap 8 fails on the unmodified library, or a Retro records a criterion dropped in a phase whose `Owns:` exceeded about 10 files.

### P-11 — Adopt after an eval. Verification: Confirmed for the source; the value is Unverified.
Evidence: `required_property` / `fix_hint` exist as described; upstream has no catch rate. The independence gap is real: the gate at `planner.md:65` is run by the planner on its own plan. Constraints: read-only fan-out is sanctioned, so no conflict; but there is no plan-review subagent shim in `Agents/`, so on Claude Code this means a new overlay or a generic subagent, and on hosts without subagents the fallback is an in-session re-read, the weakest form. Value versus cost: plan defects that matter (a dropped criterion, an unconsumed decision) are already Blocking later in QA traceability; catching them before implementation is cheaper only if the fresh-context check actually finds what the self-run gate missed. That is measurable: seed three plan defects, compare the self-run gate with a fresh-context check, record in `EVALS.md`. Each full-path feature would pay one extra pass over spec, design and plan. The `Required:` field (Target 2) lengthens a template line present in every task file to prevent a failure nobody has recorded here; ship it only together with Target 1, or when a Retro shows a finding that survived two rounds because the fix followed the hint.

### P-12 — Adopt now, both parts, each kept minimal. Verification: Confirmed.
Evidence: upstream ships the positive-control lint and 32 declined-proposal records; neither proves benefit, but neither needs to. `Scripts/` holds no test file, while `Hooks/` does, so the lints that guard the `AGENTS.md` cap and repo memory are the only gates with no proof they fire. That is the library's own `LESSONS.md:46` failure mode. Constraints: none; no Pester dependency; zero session tokens. Cost: about 150 lines of PowerShell and one fixture per future rule. To keep that bounded, cover the error rules only (E1–E7, R1–R11); warnings can wait. The ledger: note that a `## Dismissed/Declined` group was already proposed and rejected once (`library-inheritance-research-2026-10.md:288`), but for `ROADMAP.md` in a consumer repo ("ROADMAP's job is completeness"). A library-level list in `EVALS.md` is a different place and purpose, so this is not a re-litigation; the user should still see that history when deciding. Its value is shown by this sweep's own brief, which had to name two prior research files to avoid repeats. One line per entry pointing to the task file that holds the reasoning keeps it within one fact, one place.

### P-13 — Adopt now. Verification: Confirmed.
Evidence: I read `handoff-check.mjs`. Unparseable stdin returns `{}` (`:46-51`), a failed `git status` returns no changed files and therefore allows the stop (`:84-89`), and an uncaught exception exits through Node's default code 1, which is not the blocking code 2. So the hook fails open in every internal-error path, and `Hooks/README.md` says none of this; the test file has no malformed-input case (`rg -i "malformed|invalid json|empty stdin" Hooks/*.test.mjs` → nothing). Constraints: none; a README column and three or four tests; no behaviour change. Value: small but concrete: a user relying on the Stop hook cannot tell from the README that a broken hook silently stops enforcing. Write the column from the code as it is (fail open), not as a design change.

### P-14 — Defer. Verification: Probable.
Evidence: F-4: the source does not ship or test this; it is the gap author's own idea, which is fine but means zero external evidence. The motivating example ("push to main after tests" surviving a compaction) is already covered: a push is ask-first, an approval counts only when recorded in the task file in the user's words (`TASK_MEMORY.template.md` Approval line; `AGENTS.md` Handoff contract: "a claimed review or approval only with its Evidence row or recorded approval"), and Tier 3 memory "can never grant a permission". So the harmful case is closed by an existing rule. What the sentence would add is re-confirmation of every ordinary user instruction that was summarised and is not in the task file, which is over-asking after each compaction, against the Phase Protocol's "work the phases through". Trigger to revive: an `Evals/routing-cases.md` H-series case in which an injected instruction, paraphrased by a compaction summary, is followed for an action that is not ask-first.
