## 2. How it actually works

**Bootstrap (the part that makes skills fire).**
- `hooks/hooks.json` registers one `SessionStart` hook, matcher `startup|clear|compact`, `async: false`, running `hooks/run-hook.cmd session-start`.
- `hooks/session-start` (bash, no subprocesses) reads `skills/using-superpowers/SKILL.md`, JSON-escapes it and emits it as additional context wrapped as: `<EXTREMELY_IMPORTANT>\nYou have superpowers.\n\n**Below is the full content of your 'superpowers:using-superpowers' skill ...` It picks the output field per harness (`additional_context` for Cursor, `hookSpecificOutput.additionalContext` for Claude Code and Muse, top-level `additionalContext` otherwise).
- `skills/using-superpowers/SKILL.md` (3,192 bytes) is the injected text. Key lines: "If you think there is even a 1% chance a skill might apply to what you are doing, you ABSOLUTELY MUST invoke the skill." / "Invoke relevant or requested skills BEFORE any response or action — including clarifying questions, exploring the codebase, or checking files." / "announce "Using [skill] to [purpose]" and follow the skill exactly. If it has a checklist, create a todo per item." It ends with a 12-row Red Flags table ("This is just a simple question" → "Questions are tasks. Check for skills.").
- Precedence is stated inside the bootstrap: "User instructions (CLAUDE.md, AGENTS.md, GEMINI.md, etc, direct requests) take precedence over skills, which in turn override default behavior."
- Subagents are told to skip it: `<SUBAGENT-STOP>If you were dispatched as a subagent to execute a specific task, ignore this skill.</SUBAGENT-STOP>`
- Per-harness variants of the same injection: `.opencode/plugins/superpowers.js` (message transform on every agent step, V1 and V2), `.pi/extensions/superpowers.ts` (`session_start`, `session_compact`, `context` events), `.hermes-plugin/__init__.py` (`pre_llm_call` hook), `GEMINI.md` (`@./skills/using-superpowers/SKILL.md` include). Codex and Antigravity get no hook; they rely on the skill description "Use when starting any conversation" (release notes v6.1.0, v7.0.0).

**The workflow chain** (README "The Basic Workflow"; each skill names the next one):
1. `skills/brainstorming/SKILL.md` — find out what and why, play the understanding back in chunks, lay out 2-3 approaches, write a design doc to `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`, get approval. Ends in a `<HARD-GATE>`: "Nothing gets built until your human partner approves the design doc".
2. `skills/using-git-worktrees/SKILL.md` — isolate work; ask consent first; prefer the harness's native worktree tool.
3. `skills/writing-plans/SKILL.md` — plan saved to `docs/superpowers/plans/YYYY-MM-DD-<feature-name>.md`, tasks with exact files, interfaces, failing test, run command, commit step. User reviews the saved plan and picks an execution mode.
4. `skills/subagent-driven-development/SKILL.md` (fresh implementer subagent per task + fresh reviewer per task + whole-branch review) or `skills/executing-plans/SKILL.md` (same session does every task, one fresh whole-branch review at the end).
5. `skills/test-driven-development/SKILL.md` during implementation; `skills/verification-before-completion/SKILL.md` before any success claim.
6. `skills/requesting-code-review/` and `skills/receiving-code-review/`.
7. `skills/finishing-a-development-branch/SKILL.md` — verify tests, offer merge / push+PR / keep.
- Side skills: `systematic-debugging`, `dispatching-parallel-agents`, `writing-skills` (how skills are authored and tested), `diagnosing-superpowers` (post-mortem of a bad session).

**Artifacts on disk.** Design docs and plans are committed under `docs/superpowers/`. Execution scratch (ledger, task briefs, implementer reports, review diffs) lives in a git-ignored per-plan directory `<repo-root>/.superpowers/sdd/<plan-basename>/`, created by `skills/subagent-driven-development/scripts/sdd-workspace`, and is deleted after a clean final review ("the git history is the record now", `references/final-review.md`).

**Evaluation.** Two layers (`docs/testing.md`): `tests/` (bash/node/python tests of non-LLM plugin code plus a few `claude -p` behaviour scripts) and the separate eval lab `prime-radiant-inc/superpowers-evals`, meant to be cloned into `evals/` (it stopped being a submodule in v6.0.2 because it "broke plugin installs for some users").

## 3. Mechanisms

Evidence labels: **Measured** = a number is stated in a primary source; all such numbers are maintainer self-reports, small n, mostly LLM-graded, and I could not re-run or locate raw run data for them. **Incident** = a described real-session failure motivated it. **No evidence found** = nothing in the sources read.

1. **Session-start bootstrap injection.** Injects the full `using-superpowers` skill into context at startup, `/clear` and compaction. Path: `hooks/hooks.json`, `hooks/session-start`, harness ports listed in section 2. Problem: installed skills that are never invoked ("Without it, the skills are dead weight — present on disk but never invoked", `AGENTS.md`). Evidence: Measured for one harness only — Antigravity description-based bootstrap "verified ... on agy 1.3.1 across 12 runs" (v7.0.0 notes). The evals repo has scenarios `superpowers-bootstrap`, `superpowers-bootstrap-persistence` and 7 `triggering-*` scenarios; no pass rates for them were found in the files read. The long list of bootstrap-loss bugs fixed in v7.0.0–v7.0.2 (section 4) is evidence that the mechanism is fragile per harness.

2. **"1% rule" with skill-before-anything ordering.** Rule that the skill check precedes even clarifying questions and file reads. Path: `skills/using-superpowers/SKILL.md`. Problem: agent starts acting before loading process guidance. Evidence: no direct measurement found. Cost side is acknowledged: v6.1.0 "The `using-superpowers` bootstrap is injected into every session, so its size is paid for constantly."

3. **Red Flags / rationalization tables.** Two-column tables ("Thought | Reality" or "Excuse | Reality") listing the excuses an agent makes and the counter. Present in nearly every skill (the 2026-06-10 audit counts "14 recognition tables"). Problem: agent knows the rule and talks itself out of it. Evidence: Measured — deleting TDD's rebuttal prose "measurably degraded test-first behavior under 'just write it, tests after' pressure (control 8/10 → treatment 5/10, corroborated on Claude and Codex)", so the rebuttals were kept as table rows (v6.2.0 notes; scenario `evals:scenarios/tdd-holds-under-tests-later-pressure/`). Also `docs/superpowers/specs/2026-06-10-positive-instruction-redesign-design.md`: "Recognition tables work. Red-Flags/rationalization tables read at decision time".

4. **Iron Laws with explicit loophole closing.** One-line absolute rule in a code block plus enumerated forbidden workarounds: `NO PRODUCTION CODE WITHOUT A FAILING TEST FIRST` (TDD), `NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE` (verification), `NO FIXES WITHOUT ROOT CAUSE INVESTIGATION FIRST` (debugging), `NO SKILL WITHOUT A FAILING TEST FIRST` (writing-skills). Each adds "Violating the letter of the rules is violating the spirit of the rules." Path: the four `SKILL.md` files; technique described in `skills/writing-skills/references/bulletproofing.md`. Problem: "I'm following the spirit" evasions. Evidence: same 8/10 vs 5/10 result as item 3 for TDD; none found for the other three.

5. **Persuasion-principle wording.** Deliberate use of authority, commitment (forced announcements, todos per checklist item), scarcity wording. Path: `skills/writing-skills/references/persuasion-principles.md`. Problem: compliance under pressure. Evidence: cites external research only — "Meincke et al. (2025) tested 7 persuasion principles with N=28,000 AI conversations ... (33% → 72%, p < .001)". Citation not checked here: **Unverified**. No in-repo measurement.

6. **Announcement + todo-per-checklist-item commitment.** "announce "Using [skill] to [purpose]" ... If it has a checklist, create a todo per item." Path: `skills/using-superpowers/SKILL.md`. Problem: silent skipping of steps. Evidence: no evidence found.

7. **Triage before ceremony (brainstorming entry test).** "Everything that matters is in the request ... This is a quick, clear task. Do it" versus "Something non-trivial is missing. Start the conversation." Plus an opt-out line when the user did not ask for brainstorming: "Or if you'd rather I just dive in, say so." Path: `skills/brainstorming/SKILL.md` ("First: What Do You Actually Know?", "Your First Message"). Problem: full ritual applied to trivial changes. Evidence: Incident — v7.0.1: "Many of you told us, rightly, that the new default questions got annoying fast and felt formulaic" (#2530). Measured — v7.0.2: "filler questions dropped from 41 with 7.0.1 to 23" in "blind-graded test conversations".

8. **Look before you ask.** Read the referenced spec/code before the first message; "Never ask what the project or their context already answers". Path: `skills/brainstorming/SKILL.md`. Problem: questions the repo already answers. Evidence: covered by the filler-question numbers in item 7.

9. **Ask why first, open-ended.** If the motive is unknown, first question is "one open question in their own terms, with nothing to pick from"; options with a recommendation only once the why is known. Path: same file ("Get them describing"). Problem: option menus steer the user ("Options steer", Red Flags row). Evidence: Measured — "the reason behind the request came out before any approach in 33 of 33 conversations (28 of 33 before)"; against 6.4.2 "33 of 33 against 19 of 33" (v7.0.2).

10. **Play It Back in short chunks.** "describe that part back in about 200-300 words, then return to questions about the next part ... End each chunk by asking what's wrong or missing." Agent guesses are labelled: "Only what they said goes in as theirs. Anything you filled in goes in as your proposal, with your reason." First-message echo capped at "about 200 words". Path: `skills/brainstorming/SKILL.md` ("Play It Back", "Your First Message"). Problem: long specs nobody reads; silent defaults ("A default they never heard is one they couldn't reject"). Evidence: no measurement isolating chunk size found.

11. **Approaches in a message of their own.** Two or three real alternatives with trade-offs and a recommendation, sent before any write-up; recorded in an "Approaches" part of the design doc. Path: `skills/brainstorming/SKILL.md` ("Lay out the approaches", "Size the Work"). Problem: agent jumps to one design. Evidence: Measured — v7.0.2 Ctrl+K conflict scenario: 7.0.1 "asked a bare 'which one?' in 8 of 8 runs. This release laid out the options and recommended one in 8 of 8."

12. **Size the work (two sizes of design doc).** "A small change" gets a short doc, "A project" gets the full written design; "If it grows mid-task, stop, say so, and step up a size." Path: `skills/brainstorming/SKILL.md`. Problem: one fixed ceremony for all sizes (v6.3.0: "Ceremony now scales to the task"). Evidence: no measurement found.

13. **HARD-GATE on design approval.** Tagged block: nothing is built until the design doc is approved; "Building includes writing product code, scaffolding, installing dependencies, creating projects, and invoking an implementation skill." Approval scope rule: "Approval covers what you showed them. A design doc you haven't written isn't approved." Path: `skills/brainstorming/SKILL.md`. Problem: Incident — "The motivating session took 'that scope is ok' as permission to scaffold" (v6.4.1). Evidence: Measured — "it skipped the doc without asking in 24 of 24 runs before this change and 3 of 24 after" (v7.0.1); "nothing got built before approval (4 times before)" (v7.0.2).

14. **Builder check (fresh-reader review of the spec).** A fresh subagent is told "You will not be able to talk to the person who wrote it" and returns only questions where "a wrong guess would matter". The author sorts them into answered-already / minor (agent decides, marks as its call) / theirs (one batch to the user). "That's the only round of questions the check produces." Path: `skills/brainstorming/builder-check-prompt.md`. Problem: specs that look complete to their author. Replaced an earlier spec-document reviewer (v7.0.0). Evidence: no measurement found; eval scenarios `spec-reviewer-catches-planted-flaws`, `spec-writing-blind-spot` exist (the latter failed on Antigravity in `evals:docs/baselines/2026-06-09.md`).

15. **Spike exception.** A throwaway build the user agreed to may skip tests, plan and review; "keeping what it produced is a new request that comes back through this gate." Path: `skills/brainstorming/SKILL.md`. Problem: learning-by-building blocked by process. Evidence: no evidence found.

16. **Plan as decisions, not code.** A step is done "when the implementer can write exactly one reasonable thing from it"; test steps carry assertions as code, code steps carry signature + file + spec values, bodies only when the algorithm is not determined. "A plan longer than the code it describes has written the code instead." Path: `skills/writing-plans/SKILL.md` ("What a Step Contains"). Problem: Incident — some models "would sometimes try to implement the entire project while designing the plan" (v6.4.2). Evidence: Measured — "plans took a quarter of the time and about a third of the tokens"; "Every plan written by the new skill executed 9/9 against planted-defect probes on Sonnet 5, the same result as full-code plans" (v6.4.2).

17. **Plan header: Spec pointer, Global Constraints, Interfaces.** Mandatory header with `**Spec:**` path, a `## Global Constraints` block "with exact values copied verbatim from the spec", and per-task `Consumes:` / `Produces:` signatures because "A task's implementer sees only their own task". Path: `skills/writing-plans/SKILL.md`. Problem: plan conflicts "guessed at" instead of resolved against the design (v6.3.0); cross-task name drift. Evidence: eval scenarios `sdd-spec-constraint-preserved`, `sdd-spec-context-consumed` exist; no results read.

18. **Review Focus section.** Up to five input classes "the spec implies but no task's tests exercise", each then pinned by a test in the owning task. Path: `skills/writing-plans/SKILL.md`. Problem: Incident — "In evals, every implementer shipped the same crash on an input the spec implied but never named" (v6.4.1). Evidence: no post-change measurement found.

19. **Plan self-review checklist (5 checks, no subagent).** Spec coverage, step scan, type consistency, Review Focus, proportion (plan length vs spec length). Path: `skills/writing-plans/SKILL.md`. Problem: placeholders, renamed functions across tasks, plans that transcribe the program. Evidence: no evidence found. Note a separate plan-reviewer prompt was removed as unreferenced (v6.4.2).

20. **User reviews the saved plan and chooses execution mode.** Handoff message offers "Subagent-driven" or "Native" with a one-sentence recommendation drawn from the plan. Path: `skills/writing-plans/SKILL.md` ("Execution Handoff"). Problem: "Approving an idea or a scope no longer counts as approving a plan you haven't seen" (v6.4.1). Evidence: no evidence found.

21. **Fresh implementer subagent per task, fed by file.** Controller records `BASE` sha, runs `scripts/task-brief PLAN N` to extract only that task into a file, and dispatches with five fixed elements; the implementer writes a full report to a file and returns only status, commits, one-line test summary and concerns. "Never make a subagent read the whole plan file." Path: `skills/subagent-driven-development/SKILL.md`, `implementer-prompt.md`, `scripts/task-brief`. Problem: context bloat — "a real session's dispatch hit 42k chars of which 99% was pasted history". Evidence: Incident plus Measured micro-test — positive recipe produced "3.0, zero variance" re-typed spec values versus 4.4 for a prohibition and 3.6 for no guidance (opus, 5 reps; positive-instruction spec).

22. **Four implementer statuses.** `DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT`, each with a handling rule. Path: `implementer-prompt.md`, `references/handling-reports.md`. Problem: implementers that guess instead of escalating. Evidence: no evidence found.

23. **Task review as a file-based, two-verdict gate.** `scripts/review-package PLAN BASE HEAD` writes commit list + stat + `-U10` diff to one file; a fresh reviewer gets three paths (brief, report, diff) plus the verbatim constraints and must return both a spec-compliance verdict (✅/❌/⚠️) and a quality verdict with Critical/Important/Minor findings citing `file:line`. Reviewer rules: "Do Not Trust the Report", read-only checkout, no crawling beyond "one focused check per named risk", no re-running the suite, no spawning subagents. Path: `task-reviewer-prompt.md`, `scripts/review-package`. Problem: self-graded work; reviewers that wander or duplicate test runs. `review-package` "rejects empty or non-descendant BASE..HEAD ranges (exit 3), so an implementer that committed to the wrong branch can't produce a 'clean' review of nothing" (v6.4.1). Evidence: eval scenarios `sdd-quality-reviewer-catches-planted-defect`, `code-review-catches-planted-bugs`, `sdd-rejects-extra-features` exist; pass rates not found in files read. Measured for one sub-rule: "do not ask reviewer to re-run tests" prohibition gave 0/5 violations vs control 3/5.

24. **No pre-judging tripwire.** If the controller's reviewer prompt contains "do not flag," "don't treat X as a defect," "at most Minor," or "the plan chose" — "stop: you are pre-judging, usually to spare yourself a review loop." Path: `skills/subagent-driven-development/SKILL.md` step 3. Problem: controller muzzling its own reviewer. Evidence: doctrine statement "Tripwires work. Phrase-level self-checks on concrete tokens ... fire reliably" (positive-instruction spec); no number given for this tripwire.

25. **Plan-mandated defects are still findings.** If the plan itself mandates something the rubric calls a defect, the reviewer reports it "as Important, labeled plan-mandated. The plan's authorship does not grade its own work; the human decides." Path: `task-reviewer-prompt.md` (Calibration), `references/preflight.md`. Problem: a bad plan laundering bad code. Evidence: no evidence found.

26. **"Cannot verify from diff" channel.** Reviewer lists requirements it cannot check from the diff as ⚠️ items instead of widening its search; the controller must resolve each before closing the task. Path: `task-reviewer-prompt.md`, `references/cannot-verify.md`. Problem: reviewers either guess or crawl the codebase. Evidence: no evidence found.

27. **Fix loop with cap, model escalation and circuit breaker.** Max five rounds per task. Rounds 1-3 resume the original implementer with the findings verbatim; rounds 4-5 go to "a fresh implementer on a more capable model". Every round ends with a scoped re-review (`re-review-prompt.md`) that only answers ADDRESSED / NOT ADDRESSED per finding and flags new breakage in the fix diff. After round 5 the controller adjudicates each open finding and must ledger it ("a silent discard is forbidden"). The controller never fixes code itself. Path: `references/fix-loop.md`. Problem: unbounded review ping-pong and reviewers finding new things each round. Evidence: Incident — after compaction truncated the skill "subagent-driven development lost its five-round limit and ran 18 fix rounds on one task" (v7.0.1, #2481). Eval scenarios `sdd-breaker-adjudicates-at-cap`, `sdd-round4-escalates-model`, `sdd-re-review-scoped`, `sdd-fix-loop-resumes-implementer`; validation doc `evals:docs/experiments/2026-07-17-pr1998-fix-loop-validation.md` exists (not read in detail).

28. **Progress ledger as compaction-proof memory.** `<workspace>/progress.md`, first line `# SDD ledger — plan: <plan file path>`, fixed line formats (`Task <N>: complete (commits <base7>..<head7>, review clean)`, `fix round <R>/5 ...`, `parked — ... — Ruling: ...`, `minor (deferred): ...`). "After compaction, trust the ledger and `git log` over your own recollection." Resume rule in `references/resuming.md`: a ledger naming another plan is left alone. Path: `skills/subagent-driven-development/SKILL.md` (Setup), `scripts/sdd-workspace`. Problem: Incident — "controllers that lost their place have re-dispatched entire completed task sequences — the single most expensive failure observed." Evidence: Measured, and partly negative — `docs/superpowers/specs/2026-07-06-sdd-plan-scoped-workspace-eval-results.md`: the hypothesised failure (blind adoption of a stale foreign ledger) "did not reproduce" in 25/25 baseline reps; the measured harm was 6-13 extra tool calls per resume (mean 9.0), and the change "proceeded on structural grounds ... not on a demonstrated error rate."

29. **Rulings, not stalls + four stop conditions.** During execution the agent decides conflicts itself and logs `Ruling: <what you decided> — <why> — <what it costs if wrong>`; it stops only for "an irreversible or destructive operation; a security-sensitive action; a side effect outside this worktree ... (a merge, a push to a shared branch, a publish); and a plan so broken that every path forward is a guess." All rulings are replayed to the user at the end under "Rulings I made". Path: `skills/subagent-driven-development/SKILL.md`, `skills/executing-plans/SKILL.md`, `references/final-review.md`. Problem: Incident — "One donated session had sat blocked for almost nine hours on a question the controller could have decided" (v6.3.0). Evidence: the incident only; scenarios `sdd-breaker-rules-and-continues`, `sdd-escalates-broken-plan`.

30. **Pre-flight conflict scan with a required table.** Before Task 1 the controller scans the plan for contradictions; output must be a table with a row per task and per task pair sharing a file or interface. "'The scan is clean' without those rows is not a scan you ran." Path: `references/preflight.md`. Problem: asserted-but-not-done checks (v6.3.0: scan "records its checks in the ledger instead of just asserting the plan is clean"). Evidence: no measurement found.

31. **Final whole-branch review with a single fix wave.** One review on "the most capable available model" over `merge-base..HEAD`, pointed at deferred minors and parked findings; findings go to ONE fix subagent, then exactly one scoped re-review; "There is no second fix wave". Path: `references/final-review.md`, `skills/requesting-code-review/code-reviewer.md`. Problem: Incident — "a real session's final-review fix wave cost more than all its tasks combined." Evidence: scenario `sdd-final-review-single-wave`; no numbers read.

32. **Reviewer judges unstated behaviour by reasonable-user expectation + "Declined to judge" list.** Path: `skills/requesting-code-review/code-reviewer.md`. Problem: "a crash on an unnamed input no longer slides through as Minor" (v6.4.1). Evidence: no measurement found.

33. **Explicit model selection per role.** "Always specify the model explicitly when dispatching a subagent"; cheap tier for transcription-like tasks, mid-tier floor for reviewers, top tier for final review; "Turn count beats token price ... the cheapest models routinely take 2-3× the turns". Path: `skills/subagent-driven-development/SKILL.md` (Model Selection). Problem: subagents silently inheriting the most expensive session model. Evidence: one Measured claim for a variant — running the controller one layer down on a mid-tier model "measured about half the cost and wall clock" (v6.4.1). The 2-3× turns claim has no cited data.

34. **No nested subagents.** Implementers and reviewers are told never to dispatch subagents. Path: `implementer-prompt.md`, `task-reviewer-prompt.md`. Problem: Incident — "every reviewer a worker spawned duplicated the task review the controller dispatched anyway" (SKILL.md); v6.3.0 "which was producing duplicate reviews" (#2059). Evidence: incident only.

35. **Batching of small same-shape tasks.** Several small identical-kind edits go in one dispatch; the reviewer checks the diff "file by file: every listed file must have its corresponding hunk". Path: `references/batching.md`, `task-reviewer-prompt.md`. Problem: per-task subagent cost on micro-task plans. Evidence: "cutting subagent cost sharply" (v6.3.0), no figure.

36. **Native (inline) execution with script-enforced ledger.** `scripts/task-start` prints BASE; `scripts/task-done PLAN N BASE -- TEST_COMMAND` runs the test command, stores full output, and "only if the command succeeded" appends the completion line. "A failing command records nothing: the task is not complete." Path: `skills/executing-plans/SKILL.md`, `skills/executing-plans/scripts/`. Problem: the old `executing-plans` "was a 64-line stub that measured the same as running with no plugin at all" (v6.4.1). Evidence: that sentence is itself a negative result for the old version; no numbers for the new one.

37. **TDD red-green with "the project's suite defines green".** Watch the test fail for the right reason; code written before a test is deleted; run the project's test command, not just the new file. Path: `skills/test-driven-development/SKILL.md`, `writing-good-tests.md`. Problem: Measured — "When a task named one test file, sessions ran only that file in 11 of 12 probe runs, so a broken test next door went unseen" (v6.4.1). Evidence: that baseline number; post-fix rate not stated.

38. **Falsifiability rules for tests.** "name the production change that would fail the test", derive expectations independently, closing mutation check; names the "string-presence trap" and "change-detector trap". ## 4. Known weaknesses, open issues, criticisms

Drawn from the project's own release notes, docs and code comments. Issue threads themselves were not readable.

- **Bootstrap is the single point of failure and breaks per harness.** v7.0.2 alone fixes: Copilot on Windows never got it (#2189, #1225); Pi dropped it after the first prompt (#2083); OpenCode model copied the namespaced skill id and "went on without the skill" (#2583); a user prompt containing the word `EXTREMELY_IMPORTANT` turned the bootstrap off (#2197); Muse hook failed on dash (#2528); no-bash Unix exited 127 (#2503). README: "Hermes has no post-compaction hook, so a very long session that compacts over its first turn loses the bootstrap".
- **Compaction truncation silently removes rules.** 20,000-character re-attach cut led to 18 fix rounds on one task (#2481). The fix is a size test and re-read instructions; two skills sit within 2,000 bytes of the limit.
- **Brainstorming over-asks.** v7.0.0 rebuild was walked back twice in four weeks (v7.0.1, v7.0.2); the notes still say "If brainstorming still asks you something it shouldn't, please tell us" (#2530). v7.0.2 still reports 23 filler questions across 33 graded conversations.
- **Cost.** SDD "Costs a fresh context per task and per review"; "Codex re-reads SKILL.md ~500× per long session (measured 2026-06-10)"; a final-review fix wave "cost more than all its tasks combined"; the bootstrap is paid for in every session. Cost scenarios mostly failed in the one baseline matrix read.
- **Autonomy trade-off.** "Rulings, not stalls" means design conflicts are decided by the agent mid-run and surfaced only at the end; README says the agent may "work autonomously for a couple hours at a time". A wrong early ruling is built on by later tasks unless caught by the final review.
- **Review is LLM-on-LLM throughout.** Builder check, task review, re-review and final review are all subagents of the same session. No human gate between plan approval and the finishing menu. Reviewers are told not to re-run tests and to trust the implementer's reported test evidence unless a specific doubt arises.
- **Evidence quality.** All effectiveness numbers are maintainer self-reports with n between 5 and 33, mostly graded by an LLM assessor. No raw run data for the v7.0.x numbers was found in the public evals repo, whose head (2026-09-11) predates v7.0.0 (2026-10-09). Public reproducibility of the v7.0.x claims: **Unverified**. `evals:ABOUT.md` names the system under test as `superpowers-private`, so some development happens in a private repo.
- **Negative/neutral results the project itself reports:** old `executing-plans` "measured the same as running with no plugin at all"; the stale-ledger failure "did not reproduce" in 25/25 reps; `cost-*` and some spec scenarios failing in the 2026-06-09 baseline; an eval-harness audit found the Claude and OpenCode adapters returning `indeterminate` from capture bitrot (`evals:docs/audits/2026-06-13-liveness-and-bitrot-audit.md`).
- **Release hygiene.** "v6.4.0 was never shipped"; Gemini CLI support removed in v6.1.0 and restored in v6.2.0 ("premature"); a skill (`proving-it-works-with-a-movie`) held back; the evals submodule "broke plugin installs for some users" (#1778).
- **Doc drift observed at the commit read.** `.claude-plugin/plugin.json` still describes it as "Core skills library for Claude Code"; README's Muse paragraph says the bootstrap is injected by a native `SessionStart` hook "alongside Claude Code, Codex, Cursor, Gemini, Pi, and the rest" while the release notes say Codex ships no hook (v6.1.0) and Antigravity has no session-start event (v7.0.0); README says `npm test` but `package.json` defines no scripts.
- **Bus factor.** About 79% of commits are by one author, 13% by a second.
- **Skill philosophy diverges from the vendor's.** `AGENTS.md`: "Our internal skill philosophy differs from Anthropic's published guidance on writing skills." The heavy imperative style (capitals, "ABSOLUTELY MUST", "not negotiable") is deliberate and may over-trigger on newer models; the repo's own `subagent-dispatch-no-overtrigger` and `cost-checkbox-over-trigger` scenarios show the authors treat over-triggering as a live risk.
- **Windows.** Many fixes across v6.2.0–v7.0.2 (PowerShell parser errors, Git Bash paths, exec bits, `/c/Users` paths); bootstrap needs Git for Windows bash, otherwise the hook exits 0 silently and the skills do not auto-trigger.
- **Closed to outside skills.** "we don't generally accept contributions of new skills"; domain skills must be separate plugins.
- External criticism (blogs, forums, issue threads): not read — outside the primary-source scope and unreachable here.

## 5. Anything that looks unsafe

No hidden or obfuscated instructions were found: a scan of `.md`, `.json`, `.js`, `.sh` files for zero-width and bidi-control characters returned nothing; no `curl | sh`, `sudo`, or base64-decode patterns exist outside test scripts; there are no install or post-install scripts. What follows is overt but worth weighing.

- **Auto-run hook that injects high-priority instructions.** Installing the plugin registers a synchronous `SessionStart` command hook that runs on every startup, `/clear` and compaction and injects an `<EXTREMELY_IMPORTANT>` block. The injected text comes from the installed plugin directory, so a plugin update changes the standing instructions of every future session without a prompt. The script itself is small, forks nothing and reads one file.
- **Instruction-priority claims.** The injected text says skills "override default behavior" and uses absolute language ("YOU DO NOT HAVE A CHOICE"). It does place user instruction files above skills. In a repo with its own agent rules this still competes for the same "before any response" slot (for example it requires a skill check before clarifying questions).
- **Remote instruction fetch at install (OpenCode).** README tells the user to say: "Fetch and follow instructions from https://raw.githubusercontent.com/obra/superpowers/refs/heads/main/.opencode/INSTALL.md". That is an unpinned URL on `main` executed as agent instructions. The same doc installs via an unpinned `superpowers@git+https://github.com/obra/superpowers.git` spec (pinning by tag is documented as optional) and suggests `rm -rf ~/.config/opencode/skills/superpowers` for migration.
- **`--trust` in an install command.** `grok plugin install superpowers@xai-official --trust` (README).
- **Telemetry by default.** The visual companion page loads a logo from `https://primeradiant.com/brand/superpowers-visual-brainstorming-logo.png` carrying the Superpowers version (README "Visual companion telemetry"; `skills/brainstorming/scripts/server.cjs:106`). Opt-out via `SUPERPOWERS_DISABLE_TELEMETRY`, `DISABLE_TELEMETRY` or `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`. Only fires if the user accepts the companion.
- **Local web server started by the agent.** `skills/brainstorming/scripts/start-server.sh` launches `node server.cjs` in the background with `nohup`, serving agent-written HTML and receiving click events over WebSocket. Defaults to `127.0.0.1` and requires a per-session key (`?key=`, then an HttpOnly cookie; Origin check on WebSocket). Risks: `--host 0.0.0.0` is documented "in remote/containerized environments"; the key is written to `.superpowers/brainstorm/.last-token`, `server-info` and `server.log` inside the project (the doc tells the agent to remind the user to git-ignore `.superpowers/`); auth hardening was added only in mid-2026 (specs `2026-06-10-visual-companion-auth-hardening-design.md`, `2026-06-11-...-final-hardening-fixup-design.md`).
- **Long unattended execution by design.** "Do not pause to check in with your human partner between tasks"; the agent self-adjudicates conflicts. The stop list covers destructive, security-sensitive and outside-worktree actions, but classification is left to the model. No permission configuration is shipped: the plugin neither widens nor narrows tool permissions, so safety depends on the host's settings.
- **Deletion instructions in skills.** `rm -rf <workspace>` after a clean final review (`references/final-review.md`); forced branch deletion after a typed `discard`; `git worktree remove`. Past incident: worktree removal destroyed untracked files (#2016, #1223), since guarded.
- **Git writes without per-step consent.** Plans include `git add` + `git commit` in every task; design docs and plans are committed; the worktree skill may edit and commit `.gitignore`. Merge and push are behind the finishing menu.
- **Transcript handling in `diagnosing-superpowers`.** It reads full session transcripts (which can contain secrets), copies material to `~/.superpowers/diagnosing-superpowers/<session-id>/`, and can build an archive or file a public GitHub issue via `gh issue create`. Gates: bundle only on request, issue only after the user approves the exact text. Scrubbing is LLM-based and the skill itself says "scrubbing can miss things: they must review every file before sharing."
- **Past security-relevant bugs (fixed, listed for pattern):** Windows `run-hook.cmd` used to resolve `bash`/`where` from the current directory — "a repository could plant `bash.cmd` or `where.bat` and have it run at session start" (fixed v7.0.0, #2393); a debugging example "echoed the signing identity's value into logs" (fixed v7.0.0, #2375); a `%LOCALAPPDATA%`-unset path collapse is guarded in the current script.
- **Instruction-like text addressed to agents inside the repo (reported, not acted on):**
  - `AGENTS.md`: "## If You Are an AI Agent — Stop. Read this section before doing anything." followed by PR-submission rules. Benign contributor policy; relevant only to an agent opening a PR there.
  - `tests/systematic-debugging/pressure-scenarios/test-pressure-*.md` and examples in `skills/writing-skills/references/testing-skills-with-subagents.md`: "IMPORTANT: This is a real scenario. Choose and act." These are test fixtures; the first set was moved out of `skills/` in v7.0.2 because agents could take them as live instructions, but the `writing-skills` reference file with the same phrasing still ships inside an installed skill directory.
  - `.github/PULL_REQUEST_TEMPLATE.md` HTML comments addressed to submitting agents.
- **Test scripts use permission bypass.** `tests/explicit-skill-requests/*.sh` and `tests/claude-code/test-subagent-driven-development-integration.sh` call `claude -p ... --dangerously-skip-permissions` / `--permission-mode bypassPermissions`. They are maintainer tests, not invoked by any skill or hook, but they do ship in the cloned plugin directory.
- **Eval lab runs agents with safety off.** `evals:README.md` "Live Eval Risk": Claude `--dangerously-skip-permissions`, Codex `--dangerously-bypass-approvals-and-sandbox`, Gemini `--approval-mode=yolo`, Copilot `--allow-all`, with host OAuth credentials seeded into a throwaway per-run `HOME`. The README states this "narrows the blast radius but is not a sandbox." Only relevant if the eval lab is adopted, not the plugin.
