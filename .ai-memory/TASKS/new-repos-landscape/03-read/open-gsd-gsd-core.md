## 1. What it is, who maintains it, adoption signals

**What it is.** An npm-distributed prompt/workflow framework ("meta-prompting, context engineering, and spec-driven development system", `README.md`) that installs slash commands, subagent definitions, workflow prompts, hooks and a Node CLI (`gsd-tools`) into an AI coding host. Hosts named in the README: Claude Code, OpenCode, Antigravity CLI, Kimi CLI, Kilo, Codex, Copilot, Cursor, Windsurf; `capabilities/` holds 45 directories including per-host adapters (cline, augment, qwen, trae, hermes, pi, ollama, lm-studio, llama-cpp, zcode...). License MIT.

## 2. How it actually works

**Install.** `npx @opengsd/gsd-core@latest` runs `bin/install.js` (the `gsd-core` bin). It prompts for runtime and global/local scope, converts the canonical Claude-format agents/commands into each host's format, registers hooks and writes host settings. README: "The installer is required for cross-runtime compatibility — do not copy files from `agents/` or `commands/` directly." A second channel is the Claude Code plugin marketplace (`.claude-plugin/plugin.json`, `hooks/hooks.json`).

**Surfaces shipped.** 72 slash commands (`commands/gsd/*.md`), 35 agent definitions plus `.compact.md` variants (`agents/`), 109 workflow prompts (`gsd-core/workflows/`), ~120 reference fragments (`gsd-core/references/`), 35 artifact templates (`gsd-core/templates/`), ~29 hook scripts (`hooks/`), 72 skill directories (`skills/`), and a TypeScript-compiled CLI (`src/*.cts` → `gsd-core/bin/lib/*.cjs`, invoked as `gsd-tools` / `gsd_run query <verb>`).

**The loop** (`docs/explanation/the-phase-loop.md`): `Discuss → (UI design) → Plan → Execute → Verify → Ship`, per phase, phases grouped into milestones.
- Discuss → `CONTEXT.md` in the phase dir: "a structured record of decisions that the planner, executor, and verifier can all read".
- Plan (`gsd-core/workflows/plan-phase.md`, 98 KB, ~40 numbered steps) spawns researcher → planner → plan-checker as separate subagents; revision loop max 3; then requirements-coverage and decision-coverage gates.
- Execute (`gsd-core/workflows/execute-phase.md`, 94 KB): `gsd_run query phase-plan-index` returns plans grouped in waves; "Within a wave: parallel if `PARALLELIZATION=true`, sequential if `false`"; each executor is a fresh subagent, on Claude Code dispatched with `isolation="worktree"`; waves merge back before the next starts.
- Verify (`agents/gsd-verifier.md`): goal-backward check writing `VERIFICATION.md` with status `passed | gaps_found | human_needed`.
- Ship: PR creation, archive, `STATE.md` update.

**Orchestrator stays thin.** `gsd-core/references/context-budget.md`: "Never read agent definition files", "Never inline large files into subagent prompts -- tell agents to read files from disk instead", "the orchestrator routes, it doesn't execute". State lives in `.planning/` (`STATE.md`, `ROADMAP.md`, `REQUIREMENTS.md`, `config.json`, per-phase `CONTEXT.md`/`RESEARCH.md`/`*-PLAN.md`/`*-SUMMARY.md`/`*-VERIFICATION.md`).

**Deterministic core under the prose.** Many verdicts are moved out of the model into CLI verbs with typed exit codes: `gsd_run query verify.key-links`, `verify.artifacts`, `verification status`, `estimate-check --calibrated`, `worktree.base-check`, `dispatch-isolation`, `package-legitimacy check`. Example (`agents/gsd-verifier.md`): exit `0` all passed, `1` negative verdict, `66` nothing declared ("report ... as not applicable, never VERIFIED"), `69` unreadable.

**Correction to the shortlist description.** "Each plan is checked to fit a fresh context window" overstates it. What exists: (a) an LLM plan-checker dimension with task/file thresholds (blocker at 5+ tasks or 15+ files per plan), and (b) a token estimate compared to `workflow.smart_zone_tokens` where "**Over budget is a WARNING, never a blocker** (ADR-2629 Decision 5)" (`agents/gsd-plan-checker.md`, Dimension 5). No hard, measured fit check exists; `docs/explanation/context-engineering.md` itself says "Headroom tracking is a heuristic."

## 3. Mechanisms

1. **Fresh-context subagent per unit of work.** Research, planning, checking, execution, verification each run in a newly spawned agent; orchestrator only routes. Lives in: `gsd-core/workflows/plan-phase.md`, `execute-phase.md`, `agents/*.md`. Problem: quality loss as a single session's context fills ("context rot"). Evidence: reasoning only in `docs/explanation/context-engineering.md`; ADR-2629 cites external papers (e.g. NoLiMa, arXiv:2502.05167) and warns "do not cite 100000 as a measured constant". No in-repo A/B measurement of the loop's effect found.

2. **Orchestrator read-depth rules and degradation tiers.** Frontmatter-only reads of SUMMARY/VERIFICATION below a 500k window; tiers PEAK 0–30%, GOOD 30–50%, DEGRADING 50–70%, POOR 70%+ with `workflow.context_guard_mode` (`auto|warn|off`, default `warn`). Lives in: `gsd-core/references/context-budget.md`, `execute-phase-context-guard.md`. Problem: the orchestrator itself bloats. Evidence: no evidence found.

3. **Context monitor hook.** PostToolUse/Stop/SubagentStop/PreCompact hook reads usage written by the statusline hook to `/tmp/claude-ctx-{session_id}.json` and injects warnings at remaining <= 35% (wrap up) and <= 25% (stop and save state). Lives in: `hooks/gsd-context-monitor.js`, `hooks/gsd-statusline.js`, `hooks/hooks.json`. Problem: agent cannot see its own context usage. Evidence: issue refs #4285, #4985 in the header show iteration; no measured results.

4. **Plan sizing rules.** "Each plan: 2-3 tasks maximum", target ~50% context, "ALWAYS split if: More than 3 tasks; Multiple subsystems; Any task with >5 file modifications; Checkpoint + implementation in same plan; Discovery + implementation in same plan". Lives in: `gsd-core/references/context-budget.md` (Phase Sizing), `agents/gsd-planner.md`. Problem: plans too large for one executor context. Evidence: none; ADR-2629 itself calls it "a static prose heuristic [that] never checks ... against reality".

5. **Estimate + calibration loop.** Each plan carries an `estimate` block (tokens ≈ chars/4 over what the executor will touch, multiplied by a per-project `estimate-calibration` factor); SUMMARY records `actuals` on the same scale; `confidence` is "derived, not judged" from sample count (`low` <3, `med` 3–5, `high` >=6). Lives in: `docs/adr/2629-phase-effort-estimation-calibration.md`, `src/prompt-budget.cts`, plan-checker Dimension 5. Problem: sizing heuristic never checked against reality; self-rated confidence unreliable. Evidence: design cites the project's own N17 measurement (see 9); no data on calibration accuracy found. Caveat stated in ADR: actuals are not real harness token counts, because "an executor subagent cannot read its own consumption".

6. **Adversarial plan-checker with required-property findings.** Separate agent, "FORCE stance: Assume every plan set is flawed until evidence proves otherwise"; 12+ dimensions (requirement coverage, task completeness, dependency correctness, temporal coupling, key links, scope sanity, verification derivation, CONTEXT compliance, scope-reduction detection, Nyquist, cross-plan data contracts, CLAUDE.md compliance, research resolution, pattern compliance, verify-command sanity, numeric-claim authority). Every issue must carry severity (BLOCKER/WARNING/INFO), a `required_property` and evidence; "`fix_hint` is an example ... never a prescription". Lives in: `agents/gsd-plan-checker.md`. Problem: checkers "go soft" (listed failure modes: accepting plausible lists, issuing warnings for blockers "to avoid conflict with the planner"). Evidence: issue refs per dimension (#1478, #1480, #1602, #1861, #2401, #3172); no measured catch rate.

7. **Bounded revision loop with stall detection.** Check → revise → re-check, max 3 iterations; escalates early if "issue_count >= prev_issue_count" ("Revision loop stalled"); separate `REVISION_CONFLICT` return that does not consume an iteration, capped at 3. Lives in: `gsd-core/references/revision-loop.md`, plan-phase step 12. Problem: infinite or non-converging producer/checker loops. Evidence: no evidence found.

8. **Gate taxonomy.** Four types — Pre-flight (block entry), Revision (loop with cap), Escalation (pause for human), Abort (stop, preserve state) — plus a gate matrix per workflow. Lives in: `gsd-core/references/gates.md`. Problem: ad-hoc validation points with unclear failure behaviour. Evidence: none; it is a naming convention.

9. **Honest verifier: exogenous abstention.** Requirements tagged at spec time as non-inferable (`verification: backstop`) cannot be marked passed by the verifier without explicit evidence (a passing held-out/property test or directly observed behaviour); otherwise status `insufficient_spec` → `human_needed`. No "are you sure?" prompt is used. Lives in: `gsd-core/references/honest-verifier.md`, `src/probe-core.cts`, `docs/adr/550-spec-phase-probe-contract.md`. Problem: verifier confidently passes checks whose answer is not in the spec. Evidence (stated in repo, raw data not found in repo → figures Unverified by me): "confident PASS on the blind-spot check ~100% of the time (mean confidence ~0.93)"; with the external tag "100% → 17% (N17)"; asking the model to "abstain if unsure" only "100% → 67%"; ADR-550 adds "ECE 0.81". Tier caveat: sonnet "2/2 under testing", haiku "1/2, inconsistent" — very small samples.

10. **Edge-probe and prohibition-probe at spec time.** Edge-probe walks each requirement against a closed taxonomy of data/behaviour-shape edges (boundaries, adjacency, encoding, ordering); prohibition-probe covers must-NOT rules (values/safety) with a recall→precision two-stage protocol. Lives in: `gsd-core/references/edge-probe.md`, `prohibition-probe.md`, fixtures dirs beside them. Problem: specs silent on edge cases and on things the feature must never do. Evidence: "The edge-probe caught 0/8 of these [prohibitions] in controlled testing"; ADR-550 notes a "measured recall gap" in the classifier and that recall is checked "offline (N18), not asserted in CI". Raw data not in repo.

11. **Goal-backward verification with four artifact levels.** "Task completion ≠ Goal achievement": derive truths → artifacts → wiring; levels exists / substantive (stub detection) / wired / data-flow; status decision tree where "passed is ONLY valid when the human verification section is empty"; score splits `verified_truths` from `behavior_unverified` so "a clean score can no longer be reached on symbol presence alone". Lives in: `agents/gsd-verifier.md`, `gsd-core/references/verification-patterns.md`, `verifier-wiring-patterns.md`. Problem: placeholder files counted as done. Evidence: none measured.

12. **`must_haves` plan frontmatter (truths / artifacts / key_links) checked by CLI.** Deterministic verbs `verify.artifacts` and `verify.key-links` with typed exit codes; pre-wave dependency check runs key-links for upcoming plans against prior-wave artifacts. Lives in: plan template `gsd-core/templates/phase-prompt.md`, `execute-phase-between-wave-reset.md` step 7b. Problem: cross-plan wiring gaps discovered late. Evidence: issue #5170 (exit-status semantics).

13. **Verification overrides.** `overrides:` in VERIFICATION.md frontmatter to accept a known must-have failure deliberately. Lives in: `gsd-core/references/verification-overrides.md`. Problem: verify loops on items that will never pass as specified. Evidence: none.

14. **Convergence evidence gate on re-verification.** On re-verification only, bounds the anti-pattern scan so the verifier cannot invent new blockers outside the approved gap-closure contract. Lives in: `gsd-core/references/verifier-evidence-gate.md` (#3304). Problem: gap-closure never converging. Evidence: issue reference only.

15. **Nyquist validation + stated failing direction.** Plan-checker Dimension 8 requires automated verification commands per task; check 8f requires each command to state what output means failure. Lives in: `gsd-core/references/nyquist-compliance.md`, `failing-direction.md`, `agents/gsd-nyquist-auditor.md`, `/gsd-validate-phase`. Problem: unfalsifiable acceptance commands. Evidence: "#3172: a planner emitted 21 `<automated>` commands that could not run. Cargo exited non-zero ... luck, not design."

16. **Checkable baselines on count gates.** `[HEAD=<value> EXPECT<op><value>]` beside a criterion; `verify plan-structure` rejects a gate "that already holds at HEAD"; `--replay` re-measures recorded baselines. Lives in: CHANGELOG 1.21.0, `docs/adr/4309-criterion-baseline-notation.md`. Problem: gates that pass whether or not the work is done. Evidence: changelog rationale only.

17. **Wave execution in git worktrees with base checks.** Per-wave worktree manifest; `worktree.base-check` degrades a wave to sequential when the fork base diverged; executor `worktree_branch_check` and `pre_commit_head_assertion`. Lives in: `execute-phase.md`, `execute-phase-wave-guard.md`, `execute-phase-between-wave-reset.md`, `worktree-branch-check.md`. Problem: parallel executors writing to the wrong tree. Evidence (incident notes in the prompts): cwd drift "is how a wrong-base merge nearly shipped ~1000 files" (#48); stale base FATALs (#1369, #3659, #4588).

18. **Agent isolation dispatch guard (hard block).** PreToolUse hook on `Agent|Task` blocks a `gsd-executor` dispatch that omits the negotiated isolation flag. Lives in: `hooks/gsd-agent-isolation-guard.js`, `gsd-core/references/dispatch-isolation-gate.md`. Problem: "Nothing verifies the model actually copied it. When it is omitted, the executor runs and commits directly in the user's PRIMARY checkout". Stated principle: "A prose backstop cannot fix a prose defect". Evidence: #3045, #2652.

19. **Write guard against catastrophic shrink (hard block).** PreToolUse on `Write` compares payload to on-disk ROADMAP/STATE and blocks large shrink. Lives in: `hooks/gsd-write-guard.js`. Problem/evidence: "#973 ... a planner read a ~16-line window of ROADMAP.md and Write-overwrote the whole 292-line file"; and "records an agent reading the advisory, classifying it as non-binding, and reasoning past it". Stated limit: "stops accidental and single-shot collapse, not a determined agent" (sentinel file bypass).

20. **Executor deviation rules.** Rule 1 auto-fix bugs, Rule 2 auto-add missing critical functionality, Rule 3 auto-fix blockers, Rule 4 stop for architectural change; priority Rule 4 first; scope boundary ("Only auto-fix issues DIRECTLY caused by the current task's changes"; others go to `deferred-items.md`); "After 3 auto-fix attempts on a single task: STOP". Lives in: `agents/gsd-executor.md` `<deviation_rules>`. Problem: unbounded scope creep vs. over-asking. Evidence: none.

21. **Analysis-paralysis guard.** "5+ consecutive Read/Grep/Glob calls without any Edit/Write/Bash action: STOP." Lives in: `agents/gsd-executor.md`. Problem: executors reading indefinitely. Evidence: none.

22. **Checkpoints with a non-bypassable gate.** Types human-verify / decision / human-action; auto-mode auto-approves human-verify and decisions with `auto_select`; "`gate=\"blocking-human\"` is never auto-approved". Lives in: `gsd-core/references/checkpoints.md`. Problem: autonomous runs skipping decisions that need a person. Evidence: none.

23. **Destructive-git prohibition for executors.** No `git clean`, blanket restore, `reset --hard` (one exception), `update-ref` on protected branches, force push, or any `git stash` in worktrees. Lives in: `agents/gsd-executor.md` `<destructive_git_prohibition>`. Evidence: "destroying prior-wave work (#2075, commit c6f4753)"; #2924, #3819.

24. **Atomic per-task commits + phase manifest + `/gsd-undo`.** One commit per task; `gsd-tools commit` "refuses to write outside the checkout it runs in" (1.21.0); undo reverts by phase manifest with dependency checks. Lives in: executor `<task_commit_protocol>`, `commands/gsd/undo.md`, `gsd-core/references/git-integration.md`. Evidence: none measured.

## 4. Known weaknesses, open issues, criticisms

- **Weight.** Core prompts are large: `plan-phase.md` 98 KB, `execute-phase.md` 94 KB, planner/checker/verifier/executor ~48 KB each (≈12k tokens each at chars/4) before any project content. This sits oddly with a framework whose purpose is context economy; the compact variants (35) exist because of it.
- **Complexity and churn.** 15.7k-line installer, 6,628 commits, a minor release about weekly, and a 1.21.0 Fixed list of 20+ entries mostly about state/path/worktree edge cases (symlinked `$HOME`, FIFO SUMMARY files hanging commands, two orchestrators overwriting each other's isolation record, STATE marked executing after finish). Prompts embed dozens of issue-number patches; behaviour depends on long bash blocks the model must copy correctly.
- **Much of the enforcement is still prose.** The repo says so itself: hooks were added because agents "reason past" advisories (#973, #3045). Remaining prose-only barriers are documented, e.g. UI-SPEC provenance "is defense by instruction, not by capability".
- **Context-fit is not measured.** Token estimate is chars/4, actuals are re-estimates not real usage, over-budget is advisory. The 100k "smart zone" is a policy number.
- **Evidence base is thin.** The only quantified results (N17/N18 abstention and probe experiments) are stated without raw data in the repo, with tiny tier samples (2/2, 1/2). No end-to-end measurement that the loop improves delivered code. External statistics (slopsquatting rates) are uncited.
- **Bus factor.** One login in `.github/MAINTAINERS`; one author name on ~62% of commits; required approving reviews = 0 per the CODEOWNERS comment.
