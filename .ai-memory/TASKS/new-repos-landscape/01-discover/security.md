- Non-interactive run. Restatement: list 20-30 verified new/updated repos and vendor documents on prompt-injection defence, skill/plugin/MCP supply-chain scanning, sandboxing, permission baselines and hook guards. Assumptions (stated defaults): "majorly updated" = pushed after 2026-04-01 with active releases; stars/push dates are point-in-time search-API values; nothing installed or executed.

## Method and verification

- `gh` was unusable (token rejected), and `api.github.com/repos/*` plus `github.com` HTML were refused by the session proxy. Two routes worked and are the only ones used:
  - **S** = `curl -G https://api.github.com/search/repositories --data-urlencode "q=<query>" -d sort=stars` (26 queries: keyword + `created:>2026-04-01` / `pushed:>2026-04-01` + `stars:>N`, and `topic:mcp-security`, `topic:agent-security`, `topic:prompt-injection`). Stars, created and pushed dates come from this.
  - **R** = `curl https://raw.githubusercontent.com/<owner>/<repo>/HEAD/README.md` returned HTTP 200 and the README was read. Mechanism lines come from this.
- Every row below passed both S and R unless the Verified column says otherwise. Mechanism claims are the projects' own README statements, not independently tested; benchmark numbers quoted from a README are vendor-reported.
- Not reachable from this session (host not on the network allowlist), so **not listed**: `developers.openai.com` (Codex security docs), `owasp.org` rendered pages, `docs.nvidia.com`, `docs.docker.com`. Where the same material is in a GitHub repo, the repo is listed instead.
- Star counts in this result set are unusually high across the board; they are reported as returned and should be treated as a ranking signal only.

## Notable mechanisms

1. **Sign and verify instruction files, not only code.** nono (Sigstore attestation of skills, hooks, instruction files with a trusted-publisher policy) and NVIDIA/skills (detached signature per skill, unsigned dropped at publish). An instruction library is itself an AST02/AST07 supply-chain artifact: pin by commit sha, record a hash, verify before load.
2. **Scan, evaluate, then gate install.** SkillSpector + SkillEvaluator + cisco skill-scanner show the pipeline shape: static first, LLM second, deterministic decision layer last, SARIF out, baseline file for accepted findings, CI template on every skill change.
3. **Scanners say what they do not cover.** cisco ("no findings is not a guarantee"), cc-safety-net and claude-code-hooks ("not a sandbox"), agent-safehouse ("hardening layer"), ATR (withdrew its own FP numbers). A rule that names a guard should name its limit in the same line.
4. **Hooks are per-host, so publish a coverage matrix.** failproofai, aif, numbat and dcg all carry a host-by-event table. A portable library should state, per host, which prose rules have a hard-enforcement overlay and which are prose only.
5. **Protect the guard from the guarded.** Claude Code protected paths (settings, `.mcp.json`, `.git/hooks` write-denied inside allowed dirs), `ConfigChange` hooks, solongate ("a policy in a repository cannot switch it off"), managed settings a repo cannot loosen. Matches and sharpens an "agent configuration files are ask-first" rule: enforce it at the OS/hook layer.
6. **Fail closed, and fail safe on broken config.** `failIfUnavailable: true` and `allowUnsandboxedCommands: false` (Anthropic); cc-safety-net falls back to safe defaults when its config is broken instead of disabling itself.
7. **Credentials never enter the agent's environment.** coop per-instance capability token, nono phantom tokens, Claude Code credential `mask` mode with proxy substitution, cloud git proxy. Baseline rule: the agent holds a scoped stand-in, the proxy holds the secret.
8. **Deterministic information-flow checks over classifiers.** OpenAPPA labels everything read with sensitivity and trust, then checks data-to-destination on each call; ironcurtain compiles an English constitution into deterministic rules and tests them against generated scenarios before enforcing. Both measure task completion alongside attack success, since a guard that blocks valid work is also a failure.
9. **Phase-scoped tool permissions.** statewright ties tool allowlists to workflow state (review cannot edit, deploy cannot precede checks). Directly applicable to role-per-phase libraries: reviewer, QA and debugger phases get read-only tools enforced by the host, not by prose.
10. **Scope-creep as a guardable event.** stop-that-shit moves "do not do unrequested work" from AGENTS.md prose into a hook with a four-part taxonomy; its stated motive is that the prose file kept growing a rule per incident.
11. **Evidence that survives the agent.** pipelock signed action receipts, Tracekit witness-cosigned append-only log, numbat SHA-256 case bundles. An Evidence row is stronger when produced by a process the agent cannot write to.
12. **Score the harness deterministically.** harness-score (filesystem facts only) and agentshield (defenses listed, never rewarded) give a repeatable way to audit a repo's agent setup without an LLM and without a gameable score.
13. **Shared vocabulary for findings.** OWASP AST01-AST10 and MCP01-MCP10 ids, plus ATR rule ids, give reviewers citable categories for skill, plugin and MCP findings.
