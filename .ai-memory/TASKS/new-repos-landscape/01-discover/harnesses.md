# Discover: harnesses (multi-agent coding harnesses and orchestrators)

- Role: researcher. Observed: 2026-11-18. Window: new or majorly updated since 2026-04-01.
- Restatement: list 20-30 real, opened candidates for planner/worker/reviewer loops, worktree parallelism and long-running autonomous runs, with one learnable mechanism each.
- Assumptions (stated defaults): stars and push dates are the values the GitHub search API returned today; "opened" means the README was fetched with HTTP 200; mechanisms are README claims, not tested behaviour (nothing was installed or run).
- Excluded as already studied: Hermes Agent, BMAD-Method, OpenSpec, GitHub Spec Kit (+extensions), Kiro, cc-sdd, Multica, Letta Code.

## Method and verification

- Search: `GET https://api.github.com/search/repositories?q=<terms>+created:>2026-04-01&sort=stars` (17 queries: orchestrator/worktree, multi-agent harness, planner-worker-reviewer, long-running loop, agent teams, `topic:` filters, plus `pushed:>2026-09-01 created:<2026-04-01` for older repos with major updates). `gh` CLI was unusable (invalid token), so the same API was called with curl.
- Existence check per repo (column "Verified"): `R` = `https://raw.githubusercontent.com/<owner>/<repo>/HEAD/README.md` returned 200 and was read; `S` = repo row returned by the search API today with the stars/push shown.
- Vendor documents: opened with WebFetch on the URL shown.
- Not reachable from this session (network allowlist): `cursor.com`, `developers.openai.com`. Cursor's and OpenAI's own blog/doc pages are therefore NOT listed; only their GitHub material that could be opened.
- The per-repo endpoint `api.github.com/repos/<r>` was refused by the session proxy, so license and archived status were not checked.
- Confidence note: several star counts are very high for repos a few months old; star authenticity was not audited. Treat stars as a discovery signal only.

## Notable mechanisms

1. **Completion is a decision someone else makes.** Zenith's explicit stop decision, pullboard's "a different agent verifies that exact commit", foremerge's tool-run acceptance check and foreman's deny hook on self-written verification all remove the implementer's ability to declare itself done.
2. **Fail-before / pass-after as a mechanical gate.** no_human runs the offered tests on the merge base and on the new tree; tautological tests are counted before review. This is the executable form of "a test failing before and passing after".
3. **Cross-vendor or cross-family review.** omnigent, ccteam, claudexor, ARIS and agmsg route the diff to a different model family than the author; pilotfish adds a model floor for reviewer roles.
4. **Fresh context as a precondition, not a preference.** elephant-goldfish-model stops the review when fresh subagent contexts are unavailable; kander isolates execution from review physically.
5. **Approval bound to content.** foreman seals an approval with a hash and reverts it when the document changes; claudexor requires typed per-run approval for edits to gate/test paths.
6. **Claims, leases and intent instead of locks.** pullboard reopens a claim when the agent goes quiet; loopx uses a single-flight hard lease; Claude Code agent teams use file-locked claiming and dependency blocking; foremerge publishes intent and reports overlaps without locking.
7. **Declared footprint for parallel workers.** foreman's `touches` set and agent-teams' "each teammate owns different files" match the `Owns:` rule; agetor records a base commit per worktree.
8. **Failure routing by ownership.** agent-orchestrator sends failed checks, review comments and merge conflicts back to the worker that owns the branch.
9. **Hook as the enforcement point, with a host capability matrix.** harmonist's stop hook checks that reviewers ran and the handoff was written; ccteam's pre-agent hook gates every delegation; failproofai documents which hook points are verified per host.
10. **Durable, typed run state.** Puppetmaster (typed results in SQLite), ccteam (journaled flows), Managed Agents (append-only log + `wake`), pi-harness (resume/fork/retry) make resumption cheap and independent of the transcript.
11. **Budgets and watchdogs owned by the harness.** foreman's daily cost ceiling, cezar's shared parent/child budget, Orkas' repeated-call checks and idle watchdogs, Puppetmaster's budget reservations.
12. **One loop authority per session.** oh-my-claudecode warns against stacking a native goal loop with a harness loop.
13. **Graduated autonomy.** loop-engineering starts every loop report-only for a week; munder-difflin escalates only spend, destructive operations and scope change.
14. **Attention as a contract.** agentbox's inbox row ("what I did, what I need") and pullboard's `why` (the one thing blocking each item).
15. **Review hit-rate as a metric.** kander publishes how often independent review found must-fix issues (51% of batches), a measurable argument for the review phase.
