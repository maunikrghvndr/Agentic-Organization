# Discover — lens "spec-driven" (requirements → plan → tasks pipelines, EARS tooling, convergence / traceability / verification)

- Role: `researcher`. Observed: 2026-11-18. Window: created or majorly updated since 2026-04-01.
- Excluded as already studied: Hermes Agent, BMAD-Method, OpenSpec, GitHub Spec Kit (+ extensions), Kiro, cc-sdd, Multica, Letta Code.
- Method (all unauthenticated; `gh` token in this environment was invalid, so the REST API was called with `curl`):
  - **S** = `GET https://api.github.com/search/repositories?q=<query>&sort=stars&order=desc` — stars, `pushed_at`, `created_at` are the values that call returned on 2026-11-18. Queries: `spec-driven development created:>2026-04-01`, `topic:spec-driven-development created:>2026-04-01`, `topic:spec-driven-development pushed:>2026-04-01`, `spec-driven pushed:>2026-09-01 stars:>500`, `EARS requirements created:>2026-04-01`, `requirements traceability agent created:>2026-04-01`, `spec drift agent created:>2026-04-01`, `spec traceability created:>2026-04-01 stars:>10`, `sdd claude created:>2026-04-01 stars:>40`, `intent-driven development created:>2026-04-01 stars:>20`.
  - **R** = `GET https://raw.githubusercontent.com/<owner>/<repo>/HEAD/README.md` returned HTTP 200 and the README was read (first ~1.5–2k characters plus keyword greps). Every row below is S + R verified.
- Evidence limits (read before relying on a row):
  - Mechanism lines are taken from each project's own README. They are the authors' claims; no code was installed or run, and no benchmark figure was reproduced.
  - Star counts are single API observations. Several are high for young repos (e.g. 20.8k for a repo created 2026-09-13); they were not cross-checked against a second source.
  - One WebSearch pass for vendor documents returned only secondary blog/listicle pages; none was opened and none is listed. Vendor coverage here is therefore vendor-owned repositories only (`google/`, `JetBrains/`, `aws-samples/`, `responsibleai/`). **No standalone vendor document was verified.**
  - README-only depth: skill files, hooks and CLI source were not opened. Stage 2 should read those before adopting any mechanism.

## Notable mechanisms

1. **Context-blind review as a hard precondition.** EGM (#1), 2119 (#28), tenet (#17) and gsd-core (#2) all give the reviewer only the artifact and its sources. EGM goes further: if fresh subagent contexts are unavailable, the review stops rather than degrading to in-session review.
2. **Grounded vs ungrounded critics.** tenet (#17) runs one set of critics against the spec and another without it, on the premise that spec-conformance review cannot find what the spec omitted.
3. **Hash-bound approvals that expire.** 2119 (#28), mathema (#15) and artgraph (#24) bind a verdict or link to a content hash; editing the code or the requirement invalidates the approval automatically. ProductSpec (#10) does the same with pinned spec revisions.
4. **Traceability read from what executed, not what was written.** spec-flow (#29) accepts a requirement as covered only when a test carrying its id appears in the runner's report; skipped and todo tests drop out. 2119's review question ("would these tests fail if this requirement were violated?") addresses the remaining gap.
5. **Completeness vs truth, stated separately.** wrtnlabs/evidence (#23) mechanically proves every rule has an answer and leaves judging the answer to reviewers; it can use `AGENTS.md` headings as the obligation set. spec-flow and symspec likewise document what their gate cannot establish.
6. **Deterministic, no-LLM drift detection.** artgraph (#24, per-side hashes, "which side moved"), breadcrumb-sdd (#25, line-match claims in front matter), truthboard (#26, status derived from git), SpecForge (#21, compiled rule graph), plus EGM's `drift-report` skill as the LLM-side counterpart.
7. **EARS lint as a pre-gate.** vale-ears (#33), ears-checker (#34, with suggested fixes) and agent-specification-toolkit (#27, every SHALL ↔ one checkable criterion) are cheap mechanical checks that can run before any reviewer reads a spec.
8. **Cross-requirement contradiction checking.** symspec (#30) checks the requirement *set* with an SMT solver and reports "no conflict proven" with an explicit not-compared list.
9. **Approval as an explicit token, not artifact existence.** pi-sdd-kit (#22): a `.status` file is the single gate and a present `design.md` never implies approval. genkovich/sdd (#14) hard-refuses a stage whose prerequisite artifact is missing.
10. **Front-loaded questions, then a silent run.** spec-harness (#11) and interlock (#19) allow exactly one human checkpoint; afterwards reversible questions are not asked and irreversible items are parked while other tasks continue.
11. **Ceremony reduction as a release.** spec-superflow v2 (#6) cut five paths to two and four planning documents to two, with in-place escalation from `direct` to `planned`; ai-blueprint (#8) and Aegis (#5) carry explicit proportionality / fast-path rules.
12. **Bounded rework keyed by stable issue ID.** spec-superflow (#6) escalates to a human only when the *same* issue ID fails three times; agent-orchestra (#18) caps failing verification at 3 attempts in code.
13. **Plan shaped to the executor.** tenet (#17) changes task granularity by declared model capability; gsd-core (#2) verifies a plan fits a fresh context window before running it.
14. **Living plan and doctrine.** dzhng/skills (#4) re-slices the spec mid-run; tenet lets jobs flag stale doctrine for an authorized job to update; saidwhen (#31) stores "what would reopen this" beside each decision.
15. **Completion evidence includes residual risk and stop conditions.** Aegis (#5) requires covered scope and residual risk in a done-claim; ProductSpec (#10) puts "what not to build" and "when to stop and re-plan" in the spec itself; old-coder (#7) reduces human review to a test plan before and an evidence report after.
16. **Brownfield baseline before planning.** sample-specship (#12) records preserved behavior and baseline tests in a RECON phase, and returns typed validator verdicts aggregated to merge / recover / escalate.
