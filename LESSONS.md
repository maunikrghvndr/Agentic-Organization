# Engineering Lessons — self-learning, cross-project

This is the library's self-improving loop. Every agent, in every repo, reads these takeaways and applies them. When an agent learns a durable, generalizable lesson from real work, it adds one here — so the whole system gets wiser everywhere at once, not one repo at a time.

This file lives in the **role library** (beside `EngineeringTeam/`), read from the library by path like the role files — it is **not** per-repo. Do not put a copy in any repo's `.ai-memory/`.

## What belongs here

- **General, transferable takeaways** that apply across projects — e.g. "never ship mock data in production code paths." One-line, checkable, reusable.
- A hard reinforcement of a principle that keeps getting violated in practice.

## What does NOT belong here

- **Repo-specific facts** (build commands, this project's patterns, a particular gotcha) → those go in that repo's `.ai-memory/` (`PROJECT_MEMORY.md` / `wiki/`), never here.
- **Restatements of rules already in `AGENTS.md` or a role file** → don't duplicate. Capture what experience taught that isn't already written down.

## Rules for this file

- One line per lesson, phrased as a checkable takeaway with a one-line why and a date.
- Update or merge existing lessons; never add a near-duplicate.
- When a lesson becomes stable and clearly universal, **promote it into the relevant role file** (where it will be enforced) and remove it here — this file is the on-ramp, the roles are the destination.
- Keep it short. If it grows large, group by area (backend / frontend / data-ml-ai / process) with a one-line index at the top.

Format: `- <takeaway> — <why, one line>. [YYYY-MM-DD]`

## Lessons

- A pip editable install (`pip install -e`) compiles an ABSOLUTE source path into its `__editable___*_finder.py`, so renaming or moving a project directory silently breaks `import <pkg>` in every environment that installed it — grep site-packages for the old path and plan a reinstall step into any directory rename, and never judge the move "done" on file presence alone. [2026-09-24]
- When the old name is a SUBSTRING of the new one (`Benchmark.Services` → `ClinicalSummarizer.Benchmark.Services`), a naive find/replace double-applies and yields `ClinicalSummarizer.ClinicalSummarizer.…`; mask already-correct occurrences with a sentinel first, rewrite, then unmask — and grep for the doubled prefix afterwards as the proof. [2026-09-24]
- Freeze per-lane ranks before filtering and deduplication when future retrieval tuning is expected; final fused pools cannot reconstruct which stage lost a relevant item. [2026-09-21]

- Treat an LLM-provider pin used to isolate a failure as diagnostic evidence, never as authorization to change production routing; provider selection changes data recipients, capacity, cost, and compliance and therefore requires explicit agreement. [2026-09-14]

- When wiring a previously-dead configuration setting so that it finally reaches the provider, re-check what the CURRENTLY DEPLOYED value maps to — the value was set while nothing read it, so it was never validated, and "making the setting work" can silently activate the worst option you already measured. [2026-09-09]
- Map an enum-like config string with an explicit allow-list and REJECT anything unrecognised; a `switch` whose default branch means "enable the expensive path" turns a typo or a plausible-sounding value (`"minimal"`) into unbounded latency and spend with no signal anywhere. [2026-09-09]
- A non-streamed LLM call whose reasoning tokens are suppressed (`exclude:true`) is indistinguishable from a hung socket: headers land in ~1s, then zero bytes until the model stops thinking. Before rewriting the transport to stream, A/B the call with reasoning off — streaming does not surface suppressed reasoning either. [2026-09-09]

- .NET `Microsoft.Extensions.Configuration` APPENDS to a collection property that already has a default initialiser instead of replacing it — if the options class defaults a List/array AND config declares the same key, you silently get BOTH (duplicated work, doubled runtime, double-counted output). Either leave the default empty or `.Distinct()` at the use site. [2026-08-21]

- When adding a second-language toolchain, explicitly exclude its virtual/vendor environment from every repository-wide linter; `.gitignore` alone does not define flat-config lint discovery. [2026-08-21]
- Never judge a long-running job by a PIPED exit code — `cmd | grep | tail` reports the LAST command's status, so a killed/timed-out producer looks like success. Use `set -o pipefail`, capture the producer's status directly, and never impose a wall-clock `timeout` on a load whose natural runtime you have not measured; the truncation is silent and partial data looks like complete data. [2026-08-21]

- A moved public/open-data URL does not fail — it returns 200/404 with an HTML page, and any delimiter/line-based parser "succeeds" on it, silently importing page fragments as records. Validate payload SHAPE (status, content-type, magic bytes, minimum size, not-markup) before parsing anything fetched over the network. [2026-08-20]
- Never auto-follow an HTTPS→HTTP redirect for data you will treat as authoritative — .NET/HttpClient refuses scheme downgrades by default and that default is correct; find the canonical HTTPS URL instead of opting into plaintext, which is tamperable in transit. [2026-08-20]
- Choose the embedding model BEFORE writing the first vector — swapping models changes the dimension, which forces recreating every vector index and re-embedding the whole corpus; the cheapest moment to decide is while the index is still empty. [2026-08-20]
- Resume an embedding fill only when stored vectors carry verifiable model/revision provenance; equal dimensions do not prove vector-space compatibility, so an endpoint-only loader must perform a full refresh. [2026-09-12]
- Do not build a Cypher/SQL/JSON template with `str.format()`/interpolation when the target language itself uses braces — `{id: row.x}` collides with the format placeholder and raises at runtime; use a distinctive sentinel token and `replace()`. [2026-08-20]
- A query parameter cannot be a label/table/index name: `MATCH (n) WHERE $label IN labels(n)` cannot use a label index and degrades to a full scan. Inline such identifiers from a code-owned whitelist (never caller input) so the planner can use the index. [2026-08-20]
- When a subsystem's coverage is a product requirement (languages, regions, entity types), MEASURE it per-dimension with a committed baseline test rather than reasoning from one or two examples — sampling one type/language hides that the others are unreachable, and a confident-looking partial coverage is worse than an obvious gap. [2026-08-20]

- Never use mock, fake, or placeholder data in production code paths — it ships silently and corrupts real behavior; gate it behind tests/fixtures only. [2026-07-30]
- Research before building: do not hand-roll a solved problem (retries, parsing, validation, crypto, dates, HTTP, caching) when a mature, well-maintained library exists — custom versions are buggier, less secure, and unmaintained. Evaluate the dependency (maintenance/security/license/weight) and ask before adding, but reinventing is a defect. [2026-07-30]
- SDK "smart enum" types (a struct/class exposing static members, e.g. Google.GenAI's `Type.Object`) are not C# enums — you cannot `switch` on them or use them as `case`/const labels; map via equality or `ToString()`. Verify whether an SDK "enum" is a real enum before writing a switch. [2026-07-30]
- Bulk DB loaders MUST set a generous per-command timeout — DB driver defaults are short (Npgsql = 30s) and silently kill long single statements like CREATE INDEX/COPY/ANALYZE on large tables, failing mid-load after the data streamed in. Set it on the connection string (covers COPY, DDL, counts), not per-command. REINFORCED [2026-08-20]: this bites ad-hoc/TEST queries too — an unindexed predicate (e.g. `lower(col)` with no functional index) over a large table blows the default and shows up as a FLAKY test that passes warm and fails under load, not as an obvious timeout. [2026-08-01]
- Console/CLI apps must root configuration at the binary dir (`ContentRootPath = AppContext.BaseDirectory`), not the default current-directory — else `appsettings.json` silently fails to load when run from another cwd, and config (connection strings, keys) comes back empty. [2026-08-01]
- Before "freeing space" by deleting a downloaded artifact mid-workflow, check the tool re-fetches it — a resumable loader re-downloads a deleted zip on its next run, wasting the bandwidth you tried to save. Delete derived staging only after the consuming step is done. [2026-08-01]
- Derive displayed state from the authoritative source of record (the moves/events), not a denormalized status field that can drift stale — a legacy/partial write leaves the flag wrong while the underlying data is right, and the read self-heals. [2026-08-13]
- When a reported bug won't reproduce on current code, reproduce against what's actually deployed AND test the persisted/stored-data path (e.g. craft the legacy record) before concluding "works for me" — the defect often lives in old data, not new code. [2026-08-13]
- To reset a display value derived from data (day number, ranking, sequence), change the computation's ORIGIN (a start-date/offset constant) — never delete the underlying source rows to force the number. Deleting data to move "day 1" loses content for no reason; a genesis constant achieves the same display with zero data loss. [2026-08-15]
- Never gate a server-side reveal/authorization on a client-supplied progress counter (guessNumber, step, page, attempt#) — the client forges it in one request. Bind progress into a server-signed, context-bound HMAC token the client echoes back each step; the server increments+re-signs, so the count can't be jumped. Stateless, no DB. [2026-08-15]
- A secret committed to git is compromised the moment it's pushed, even to a PRIVATE repo (collaborators, clones, CI, forks retain it) — rotate FIRST, then purge history; deleting the file is not enough. A repo-tracked "env.txt"/scratch file is a classic leak vector even when nothing reads it. [2026-08-15]
- Treat unresolved authentication as a protected state: pause authoritative interactions and account analytics until the session check resolves — initializing UI as “guest” can let a returning signed-in user act on stale device data. [2026-08-15]
- Never let a client-supplied “practice”, “preview”, or “dry-run” flag bypass an authoritative write unless the server independently proves that bypass is permitted for that user and record. [2026-08-15]
- A fail-closed config resolver (throws when a required prod secret is missing/weak) will crash any code path that calls it OUTSIDE a request try/catch, surfacing as an opaque generic 500/503 far from the real cause — a helper commented "never throws" can still throw via such a resolver. Give the throw a distinctive error name, and log SQLSTATE `code`+`constraint` (never pg `message`/`detail` — they echo row data/PII) so the masked failure is diagnosable. [2026-08-16]
- When production fails but CI is green and it won't reproduce locally, suspect env/secret/schema drift first: a dev fallback secret (or a mocked-out DB in the only test) hides a prod-only fail-closed throw that never runs in dev/CI. [2026-08-16]
- When auditing or mass-migrating CSS typography, a `font-size:` grep silently under-reports — the `font:` shorthand (`font:600 30px var(--x)`) hides a size from it, and media-query overrides hide more. Drive the migration from COMPUTED styles in a real browser, and match the shorthand too; source-only greps leave a partial migration that still looks done. [2026-08-25]
- A text-keyed i18n dictionary (translations looked up by exact rendered string) turns every copy edit into a silent localisation regression that type-checking, linting and the build all pass — changing a label's text drops it back to the source language with no error anywhere. When editing rendered strings, grep the dictionary for the OLD string and assert the translated NEW string in a test. [2026-08-25]
- Never run a blanket regex find-and-replace over a data file (i18n dictionary, config, fixture) to clean up characters: the same characters are often the file's own STRUCTURE (quote/comma delimiters) or legitimate DATA (an encoding-repair map), so the sweep silently deletes separators and corrupts it. Operate inside parsed string literals only, and syntax-check the file immediately after. [2026-08-25]
- Assigning `element.textContent` DESTROYS the child text node and creates a new one. Any layer that keyed state to that node object (i18n originals in a WeakMap, ranges, selection, observers) silently loses it, and the damage only shows up on a later interaction such as switching language back. To animate or patch text in place, mutate `node.nodeValue` and preserve node identity. [2026-08-25]
- Verify redaction through the real checkpoint or persistence adapter, not just a pure helper test — an unused sanitizer can pass unit tests while the framework still stores complete sensitive state. [2026-09-10]
- Before rewriting any document, check it is tracked (`git ls-files <path>`) and extend it with dated notes instead of replacing it — an untracked design contract that gets overwritten survives only in a session transcript. [2026-09-11]
- Treat an LLM checker's missing verdict as "unknown" (retry or stop), never as a negative verdict — mapping "no answer" to "reject" silently deleted 14 of 22 correct facts in one batch. [2026-09-11]
- For a multi-hour reference-data fill, never delete the active read index at job startup: use deterministic-id upserts or build a staged generation and swap only after verification, so interruption cannot replace usable data with a partial index. [2026-09-12]
- Validate each embedding model's serving precision with a finite, non-zero output probe; a healthy server and model-list response do not prove that FP16 inference produces usable vectors. [2026-09-12]
- Stamp code-owned provenance and ordering fields into an artifact after the generative step, and make downstream consumers read the artifact body rather than reconstructing them from filenames; otherwise a naming convention silently becomes a competing source of truth. [2026-09-15]
- Downloading a Hugging Face model by explicit commit sha does NOT create the `refs/main` pointer, so any model whose own remote code re-resolves itself by repo id (`AutoTokenizer.from_pretrained(self.name_or_path, ...)`) fails under `HF_HUB_OFFLINE` with a misleading "couldn't connect" error while the files are sitting in the cache; pin the sha AND materialise the ref. [2026-09-18]
- Check model SDK per-field token caps separately from total context limits: comparing small and enlarged sequence budgets can miss option text clipped identically in both paths, invalidating confidence evaluation. [2026-09-22]
- When two layers index the same text by offset, make one shared function hand both of them that text; a basis disagreement (raw vs corrected, NFC vs NFD, code points vs UTF-16) produces no error anywhere and only shows up as a citation pointing at the wrong characters for the minority of records where the two differ. [2026-09-29]
- A table with a schema, a validator and tests but NO caller is not a feature; before declaring a phase done, grep for the write path and check the row count. Validators tested in isolation pass forever while the table stays empty. [2026-09-29]
- Place a write that records WHY a decision was made at the step that made it, not at the final persistence step: intermediate stages routinely drop the failed/rejected items, so writing later silently keeps the explanation only for the successes -- the opposite of who needs it. [2026-09-29]
- Never let a rule's enforcement depend on how many instances of a thing are configured: "unknown value is rejected only when there are two backends" means the same violation is silent today and fatal after an unrelated scaling change, so the defect surfaces as a config change instead of at introduction. [2026-09-29]
- A check whose population is empty must report NOT MEASURABLE, never PASS: "0 dangling out of 0" is arithmetic, not evidence, and an integrity report that greens on an empty table is worse than none. Make unmeasurable exit non-zero too, and always print numerator/denominator instead of a percentage. [2026-09-29]
- When a test must construct its own input, assert in the test suite itself that it does NOT prove the end-to-end path -- a plain comment gets read as coverage, and "19/19 passing" then gets quoted as evidence the real pipeline was exercised. [2026-09-29]
- Cross-language contracts (offset bases, id formats) belong in ONE data fixture both sides read, not in two implementations of the same rule; and every case in it must be one where the wrong interpretation gives a different answer, or it proves nothing. [2026-09-29]
- Never apply a regular expression to content a human, a scanner or a model produced: it is a parser for a grammar nobody wrote down, it passes its own tests, and it fails silently on the next document. A derived value has exactly two homes -- a vocabulary resolves it, or a model reads it; "code parses it" is not a third option, and forbidding regex without naming the replacement just produces a worse hand-rolled parser. [2026-10-04]
- A reason code that fires from two or more distinct checks will be read as naming the first one, and the aggregate then misdirects the fix: 31 of 82 facts logged as `unclear_subject` had a correct subject and failed a separate assertion check. Give each refusal its own code, or the per-cause counts are unrecoverable from the log. [2026-10-05]
- When an instruction document and a runtime gate disagree, the model obeys the document and the gate gets blamed: a prompt saying a record takes "ONLY" field X, while the gate also requires Y and Z, loses every such record and looks like a model failure. Test the document against the gate, not just the gate. [2026-10-05]
- Before building on an upstream signal, measure it on real data rather than reading its field name: a per-page `date_hint` was the date PRINTED on the page (fax, print, request), not the event date, and self-consistency between its own forward/backward continuation flags was 10 of 17. A plausible field name is not a measurement. [2026-10-05]
- A regex in source is unreviewable by eye: a stray control byte makes it match NOTHING and it still compiles, passes review and reads correctly -- a dose filter ending in a literal 0x08 (a mangled ``) returned false for every input for as long as it existed, and its caller silently imported the values it was there to reject. Any pattern over data worth filtering needs a test that proves it matches something, not only that it rejects something. [2026-10-05]
- A "send only what is needed" invariant must be pinned by a test on what the PAYLOAD carries, not on what the question asks: at unit-fixture scale "the whole batch" and "the minimal context" are the same bytes, so the waste is invisible until measured on a production-sized trace -- capture one early and diff payload against need. [2026-10-05]
- Before widening or removing a broad refusal, enumerate what it refused INCIDENTALLY: a closed catalog that rejects unknown keys is often the only thing standing between an unrelated contract rule and the store (here, a group-level claim smuggled onto a record), and the replacement must refuse those cases BY NAME or the loosening silently repeals rules nobody listed. [2026-10-05]
- A gate that discards a whole correct record to enforce an optional-field vocabulary is backwards: close the set only over what code actually consumes (identity, enums, shapes it parses), and let stated-but-undeclared detail pass through visibly -- losing real data to a naming catalog is a defect, not rigour. [2026-10-05]
- A pin on a THIRD PARTY's catalog (a provider list, a quantization filter, a model id) is a liveness dependency that can break overnight with zero code change: preflight must probe the pinned thing itself, not just your own services -- a 404 discovered mid-run cost the run what a one-call preflight probe would have named first. [2026-10-06]
- Write an owner's rule down in the owner's own words and scope, never a narrower technical reading: "no regex or string matching" was recorded as "no regex", every later session read string methods as permitted, and code was built on the gap. A rule that exists only in conversation is not a rule. [2026-10-06]
- A prompt never contains real data or hardcoded data (owner rule, 2026-10-06): no value from a real record and no case-specific content. Worked examples lifted from the document being debugged carry real names, dates and ids to an external model on every call and teach the model one case instead of the rule. Invent every example, check it against the real data before saving, and never carry an old example forward unchecked. Promoted to prompt-engineer, ai-engineer and ai-reviewer. (2026-10-06)
- Turning on log export (e.g. a logging bridge flag such as Serilog `writeToProviders`) makes every EXISTING log line external at once: audit all log sites and exception messages for sensitive payloads before flipping it, because leaks that were harmless on a local console become live the moment the exporter receives them. (2026-10-06)
- A pre-validator's required-field list must come from the same source as the prompt's field list, or be pinned by a test against it: a field dropped from the prompt but left in the validator fails every obedient answer, and the same defect recurred twice in one pipeline before it was pinned. (2026-10-06)
- Size client concurrency to the narrowest transport hop, not the backend behind it: 128 parallel requests that a vLLM server handles easily closed the single SSH tunnel they all shared, and the "server down" diagnosis pointed at the wrong layer. Count every multiplexed hop (tunnel, proxy, NAT) as its own capacity limit. (2026-10-07)
- A "heal" that silently rewrites structure can destroy valid input: a count-healer that saw zero list markers rewrote [N] to [0] and emptied a correct answer, and the model was then blamed for not returning what it returned. A repair may only ADD what is unambiguous (markers, counts raised to items present); every ambiguous shape goes to the strict parser so the failure is loud and attributable. (2026-10-07)
- "No match" from a lookup is three different failures, not one -- vocabulary absent, right concept retrieved but refused (policy/type gate), or right concept never retrieved -- and each needs a different fix: before removing a category from coding OR loosening the acceptance bar, measure per failing item whether the canonical code is in the stored candidate list and at what rank. "Present in the reference store" is not "retrievable": abbreviations and same-vocabulary part/answer codes kept the right code out of 41/49 failures, where loosening the bar would have written wrong codes. [2026-10-07, corrected same day]
- A filter that both admits candidates AND gates automatic acceptance must be split before it is widened: widening for recall also widens what can auto-accept, and "sole surviving match" turns short/ambiguous inputs into confident wrong answers. Keep admission wide (send to review) and acceptance at the previously trusted set, and evaluate with NEGATIVE probes (abbreviations, single words, units) drawn by someone other than the author -- a spelled-out test set passes while the real risk is invisible. [2026-10-08]
- Export from a search index in pages (scroll / search_after via the client's scan helper), never one big request: a single 10,000-hit search over 1,918 documents carrying 4,096-dim vectors hung a 2 GB single-node cluster for 50 minutes (504s on every call, including unrelated indices, until restarted), and the one-request form also silently capped the export at the hit limit. A backup-then-delete must also refuse when the exported count is below the source count. [2026-10-08]
- In a per-item batch write, run every per-item check read-only BEFORE the item's first write, and never let one item's database refusal discard the rest: checks that ran after the write (and returned an error instead of rolling back) left facts stored AND reported refused, and one unchecked value used as a property name failed a 39-item transaction whose catch then refused every item. Name each refusal's cause; one code for five causes is unanswerable. [2026-10-08]
- Score extraction by whether the downstream question can be answered from the store, per entity (e.g. per visit), against an independent reference cut to the same source locations -- never by fact counts or batches committed: a run that "saved 341 facts" held only 7.6% of the reference findings complete in the graph, while 93% sat in raw text or a review queue, unlinked to any visit or date. A reference whose claims cite source pages can be scoped exactly to what was processed. (2026-10-14)
- Route-withdrawal guards must mirror the router's case and URI-decoding semantics; test mixed-case and percent-encoded aliases because raw prefix checks can pass while the framework still opens the withdrawn page. [2026-10-15]
- Asking a sampled model (temperature > 0) the same question twice is not independent confirmation: when an empty or negative answer is "verified" by a second read of the same input, first replay the identical request body N times and measure P(empty) -- one reader returned the empty skeleton for intact pages 50% of the time on the first ask and 20% on the confirming ask, so about 1 run in 10 wrote "verified empty" for a batch that held facts, and the coincidence was blamed on an unrelated environment change. (2026-10-17)
- An acceptance check that reads an EMPTY scope must never be mistaken for a measurement: before trusting any store check, run it once on a store you know holds data and confirm a non-zero population. (2026-10-16: ids read from a Windows program into bash kept a trailing CR, so every scoped query matched nothing and three runs' checks were void while the export of the same runs held 450+ facts.)
